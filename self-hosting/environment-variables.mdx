## Overview

Autumn requires several environment variables to function. Configuration is split between the server (`server/.env`) and frontend (`vite/.env`).

## Required Variables

These variables **must** be set for Autumn to function:

### Authentication

```bash server/.env
BETTER_AUTH_SECRET=your-secret-key-here
BETTER_AUTH_URL=http://localhost:8080
CLIENT_URL=http://localhost:3000
```

<ParamField path="BETTER_AUTH_SECRET" type="string" required>
  Secret key for signing auth tokens. Generate with: `openssl rand -base64 32`
</ParamField>

<ParamField path="BETTER_AUTH_URL" type="string" required>
  URL where your server is accessible (backend URL)
</ParamField>

<ParamField path="CLIENT_URL" type="string" required>
  URL where your frontend is accessible (dashboard URL)
</ParamField>

### Database

```bash server/.env
DATABASE_URL=postgresql://user:password@host:5432/autumn
```

<ParamField path="DATABASE_URL" type="string" required>
  PostgreSQL connection string. Get from Supabase dashboard via the "Connect" button, or use your own PostgreSQL instance.
</ParamField>

<Tip>
  For Supabase: Navigate to your project dashboard and click "Connect" in the upper navbar to find your connection string.
</Tip>

### Stripe Webhooks

```bash server/.env
ENCRYPTION_IV=generated-by-setup
ENCRYPTION_PASSWORD=generated-by-setup
STRIPE_WEBHOOK_URL=https://your-subdomain.loca.lt
LOCALTUNNEL_RESERVED_KEY=your-localtunnel-key
```

<ParamField path="ENCRYPTION_IV" type="string" required>
  Initialization vector for encrypting Stripe keys. Auto-generated by `bun setup`.
</ParamField>

<ParamField path="ENCRYPTION_PASSWORD" type="string" required>
  Password for encrypting Stripe keys. Auto-generated by `bun setup`.
</ParamField>

<ParamField path="STRIPE_WEBHOOK_URL" type="string" required>
  Public URL where Stripe can send webhooks. Auto-configured by `bun setup` for local development.
</ParamField>

<ParamField path="LOCALTUNNEL_RESERVED_KEY" type="string">
  Reserved subdomain key for localtunnel. Required for consistent webhook URLs in development.
</ParamField>

<Warning>
  Never commit `ENCRYPTION_IV` or `ENCRYPTION_PASSWORD` to version control. These encrypt your Stripe secret keys.
</Warning>

### Redis

```bash server/.env
REDIS_URL=redis://localhost:6379
```

<ParamField path="REDIS_URL" type="string" required>
  Redis connection string. Default connects to local Valkey container. For production, use [Upstash](https://upstash.com) or another managed provider.
</ParamField>

## Optional Variables

### Google OAuth

```bash server/.env
GOOGLE_CLIENT_ID=your-client-id
GOOGLE_CLIENT_SECRET=your-client-secret
```

Enable "Sign in with Google" functionality. Get credentials from [Google Cloud Console](https://console.cloud.google.com/apis/credentials).

<ParamField path="GOOGLE_CLIENT_ID" type="string">
  OAuth 2.0 Client ID from Google Cloud Console
</ParamField>

<ParamField path="GOOGLE_CLIENT_SECRET" type="string">
  OAuth 2.0 Client Secret from Google Cloud Console
</ParamField>

### Email (Resend)

```bash server/.env
RESEND_API_KEY=re_your_api_key
RESEND_DOMAIN=yourdomain.com
```

Send transactional emails (password resets, welcome emails, OTP codes). Sign up at [resend.com](https://resend.com).

<ParamField path="RESEND_API_KEY" type="string">
  API key from Resend dashboard
</ParamField>

<ParamField path="RESEND_DOMAIN" type="string">
  Verified domain for sending emails
</ParamField>

### Storage (Supabase)

```bash server/.env
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_KEY=your-service-role-key
```

Optional file storage integration.

<ParamField path="SUPABASE_URL" type="string">
  Project URL from Supabase: Settings → Configuration → Data API → Project URL
</ParamField>

<ParamField path="SUPABASE_SERVICE_KEY" type="string">
  Service role key from Supabase: Settings → Project Settings → API Keys → service_role
</ParamField>

### Webhooks (Svix)

```bash server/.env
SVIX_API_KEY=your-svix-api-key
```

<ParamField path="SVIX_API_KEY" type="string">
  Enable webhooks using [Svix](https://www.svix.com) for reliable webhook delivery to your application.
</ParamField>

### Observability

```bash server/.env
# Logging (Axiom)
AXIOM_TOKEN=your-axiom-token

# Analytics (ClickHouse)
CLICKHOUSE_URL=https://your-clickhouse.com
CLICKHOUSE_USERNAME=default
CLICKHOUSE_PASSWORD=your-password
CLICKHOUSE_SKIP_ENSURES=false
```

<ParamField path="AXIOM_TOKEN" type="string">
  Send Pino logs and OpenTelemetry data to [Axiom](https://axiom.co)
</ParamField>

<ParamField path="CLICKHOUSE_URL" type="string">
  ClickHouse instance URL for storing usage events
</ParamField>

<ParamField path="CLICKHOUSE_USERNAME" type="string">
  ClickHouse username (usually "default")
</ParamField>

<ParamField path="CLICKHOUSE_PASSWORD" type="string">
  ClickHouse password
</ParamField>

<ParamField path="CLICKHOUSE_SKIP_ENSURES" type="boolean" default="false">
  Skip creating SQL views and functions. Set to `true` after first run to speed up startup.
</ParamField>

### AI Features

```bash server/.env
ANTHROPIC_API_KEY=sk-ant-your-key
```

<ParamField path="ANTHROPIC_API_KEY" type="string">
  Generate singular/plural names for features. Used in dashboard and UI components.
</ParamField>

## Frontend Variables

```bash vite/.env
VITE_FRONTEND_URL=http://localhost:3000
VITE_BACKEND_URL=http://localhost:8080
```

<ParamField path="VITE_FRONTEND_URL" type="string" required>
  URL where the Vite frontend is accessible
</ParamField>

<ParamField path="VITE_BACKEND_URL" type="string" required>
  URL where the backend API server is accessible
</ParamField>

## Docker Environment Variables

When running with Docker Compose, additional variables are set:

```yaml docker-compose.yml
environment:
  - NODE_ENV=development
  - REDIS_URL=redis://valkey:6379
  - CHOKIDAR_USEPOLLING=true  # Windows only
  - WATCHPACK_POLLING=true     # Windows only
```

<ParamField path="NODE_ENV" type="string">
  Set to `development` or `production`. Affects logging, caching, and optimizations.
</ParamField>

<ParamField path="CHOKIDAR_USEPOLLING" type="boolean">
  Enable file watching with polling (required for Docker on Windows)
</ParamField>

<ParamField path="WATCHPACK_POLLING" type="boolean">
  Enable webpack polling (required for Docker on Windows)
</ParamField>

## Setup Script

The `bun setup` command automates environment configuration:

1. Copies `.env.example` to `.env` files
2. Generates secure random values for encryption keys
3. Creates Supabase project (optional)
4. Configures localtunnel for webhook testing
5. Validates all required variables are set

Run `bun setup` before your first deployment, or when adding new variables.

## Security Best Practices

<Warning>
  - Never commit `.env` files to version control
  - Rotate secrets regularly in production
  - Use strong random values for all keys
  - Restrict database user permissions
  - Use TLS for all production connections
</Warning>

<Tip>
  Store production secrets in a secrets manager like AWS Secrets Manager, HashiCorp Vault, or use environment variables provided by your hosting platform.
</Tip>
