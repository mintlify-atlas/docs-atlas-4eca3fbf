---
title: "Update Feature"
openapi: "POST /features/{feature_id}"
---

## Overview

Update an existing feature's configuration. You can modify the name, display settings, event tracking, credit schema, and archival status.

<Warning>
**Important Considerations**:
- Changing `type` or `consumable` affects how the feature tracks usage going forward
- Historical usage data is not recalculated
- Existing customer entitlements are not automatically updated
- Consider creating a new feature for major structural changes
</Warning>

## Path Parameters

<ParamField path="feature_id" type="string" required>
  The unique identifier of the feature to update (e.g., `api-calls`, `storage-gb`).
</ParamField>

## Request Body

All fields are optional. Only include the fields you want to update.

<ParamField path="id" type="string">
  Change the feature's ID. Use with caution as this affects all API calls referencing this feature.
  
  <Warning>
  Changing the ID will break existing `/track` and `/check` calls using the old ID.
  </Warning>
</ParamField>

<ParamField path="name" type="string">
  Update the human-readable name displayed in dashboards and customer interfaces.
</ParamField>

<ParamField path="type" type="string">
  Change the feature type: `metered`, `boolean`, or `credit_system`.
  
  <Warning>
  When changing to `metered`, you must also specify `consumable`.
  </Warning>
</ParamField>

<ParamField path="consumable" type="boolean">
  Update whether the feature tracks consumable usage.
  
  **Required when**:
  - Changing `type` to `metered`
  - Cannot be set to `false` for `credit_system` features
</ParamField>

<ParamField path="event_names" type="array">
  Update the array of event names that trigger usage tracking.
  
  ```json Example
  ["api_call", "api_request", "endpoint_hit"]
  ```
  
  <Info>
  Changes to `event_names` only affect new events. Past usage remains unchanged.
  </Info>
</ParamField>

<ParamField path="credit_schema" type="array">
  Update the credit conversion rates for `credit_system` features.
  
  <Expandable title="Credit Schema Item">
    <ParamField path="metered_feature_id" type="string" required>
      ID of the metered feature this credit can be spent on
    </ParamField>
    
    <ParamField path="credit_cost" type="number" required>
      How many credits are deducted per unit of the metered feature
    </ParamField>
  </Expandable>
  
  ```json Example
  [
    {
      "metered_feature_id": "api-calls",
      "credit_cost": 2
    },
    {
      "metered_feature_id": "storage-gb",
      "credit_cost": 150
    }
  ]
  ```
</ParamField>

<ParamField path="display" type="object">
  Update display settings for proper pluralization.
  
  <Expandable title="properties">
    <ParamField path="singular" type="string">
      Singular form (e.g., "API Call")
    </ParamField>
    
    <ParamField path="plural" type="string">
      Plural form (e.g., "API Calls")
    </ParamField>
  </Expandable>
</ParamField>

<ParamField path="archived" type="boolean">
  Archive or unarchive the feature.
  
  **Archived features**:
  - Stop accepting new usage events
  - Preserve historical usage data
  - Remain attached to existing customer entitlements
  - Don't appear in product configuration UI
  - Don't appear in list features endpoint (by default)
</ParamField>

## Examples

### Update Display Names

```json
{
  "display": {
    "singular": "API Request",
    "plural": "API Requests"
  }
}
```

### Add Event Names

```json
{
  "event_names": ["api_call", "api_request", "endpoint_hit"]
}
```

### Update Credit Conversion Rates

```json
{
  "credit_schema": [
    {
      "metered_feature_id": "api-calls",
      "credit_cost": 2
    },
    {
      "metered_feature_id": "storage-gb",
      "credit_cost": 150
    },
    {
      "metered_feature_id": "compute-hours",
      "credit_cost": 75
    }
  ]
}
```

### Archive a Feature

```json
{
  "archived": true
}
```

### Change Feature ID

```json
{
  "id": "api-requests"
}
```

<Warning>
Changing the feature ID requires updating all `/track` and `/check` calls in your application code.
</Warning>

## Response

Returns the updated feature object with all properties.

```json Example Response
{
  "id": "api-calls",
  "name": "API Calls",
  "type": "metered",
  "consumable": true,
  "event_names": ["api_call", "api_request", "endpoint_hit"],
  "display": {
    "singular": "API Request",
    "plural": "API Requests"
  },
  "archived": false
}
```

## Validation Rules

<Warning>
- **Type change to metered**: Must specify `consumable`
- **Credit system features**: Cannot set `consumable: false`
- **Credit schema**: Can only reference existing metered features
- **Feature ID**: Must be unique and match regex pattern `^[a-z0-9-_]+$`
</Warning>

## Error Responses

<ResponseField name="404" type="error">
  Feature not found. The specified `feature_id` does not exist.
  
  ```json
  {
    "message": "Feature with id api-calls not found",
    "code": "feature_not_found"
  }
  ```
</ResponseField>

<ResponseField name="400" type="error">
  Validation error. Check the error message for details.
  
  ```json
  {
    "message": "Consumable is required when changing type to metered",
    "code": "validation_error"
  }
  ```
</ResponseField>

## Common Update Patterns

### Rename Feature

Update the display name without changing the ID:

```json
{
  "name": "API Requests",
  "display": {
    "singular": "API Request",
    "plural": "API Requests"
  }
}
```

### Adjust Credit Costs

Modify credit conversion rates:

```json
{
  "credit_schema": [
    {
      "metered_feature_id": "api-calls",
      "credit_cost": 1.5
    },
    {
      "metered_feature_id": "storage-gb",
      "credit_cost": 125
    }
  ]
}
```

### Deprecate Feature

Archive without deleting:

```json
{
  "archived": true
}
```

<Info>
Archiving preserves historical data and existing customer entitlements while preventing new usage.
</Info>
