## Overview

Webhooks notify your application when important events happen in Autumn. Use webhooks to:

- **Provision access** - Grant features when customers subscribe
- **Handle cancellations** - Revoke access when subscriptions end
- **Process payments** - React to successful or failed payments
- **Sync data** - Keep your database in sync with billing events
- **Send notifications** - Email customers about billing changes
- **Update analytics** - Track subscription metrics in real-time

Autumn sends HTTP POST requests to your webhook endpoint whenever events occur.

## Setting Up Webhooks

<Steps>
  <Step title="Create a webhook endpoint">
    Create an endpoint in your application to receive webhook events:

    ```typescript
    import { Webhook } from "svix";

    app.post("/webhooks/autumn", async (req, res) => {
      const rawBody = await req.text();
      const headers = req.headers;

      // Verify the webhook signature
      const wh = new Webhook(process.env.AUTUMN_WEBHOOK_SECRET);
      
      try {
        const event = wh.verify(rawBody, {
          "svix-id": headers["svix-id"],
          "svix-timestamp": headers["svix-timestamp"],
          "svix-signature": headers["svix-signature"]
        });

        // Process the event
        await handleWebhookEvent(event);

        return res.json({ success: true });
      } catch (err) {
        return res.status(400).json({ error: "Invalid signature" });
      }
    });
    ```
  </Step>

  <Step title="Configure in dashboard">
    Add your webhook URL in the Autumn dashboard:

    1. Go to Settings → Webhooks
    2. Click "Add Endpoint"
    3. Enter your webhook URL (e.g., `https://yourapp.com/webhooks/autumn`)
    4. Select which events to receive
    5. Copy your webhook signing secret
  </Step>

  <Step title="Test the integration">
    Send a test event from the dashboard to verify your endpoint is working:

    ```bash
    # The dashboard will send a test event
    # Check your logs to confirm receipt
    ```
  </Step>
</Steps>

## Webhook Events

Autumn sends webhooks for the following events:

### Customer Product Events

**`customer.product.created`** - Customer subscribed to a product

```json
{
  "type": "customer.product.created",
  "data": {
    "customer_id": "customer_123",
    "product_id": "pro_plan",
    "status": "active",
    "scenario": "subscription_started"
  }
}
```

**`customer.product.updated`** - Product status or configuration changed

```json
{
  "type": "customer.product.updated",
  "data": {
    "customer_id": "customer_123",
    "product_id": "pro_plan",
    "status": "active",
    "scenario": "subscription_renewed"
  }
}
```

**`customer.product.deleted`** - Subscription canceled or expired

```json
{
  "type": "customer.product.deleted",
  "data": {
    "customer_id": "customer_123",
    "product_id": "pro_plan",
    "status": "canceled",
    "canceled_at": "2026-02-17T12:00:00Z"
  }
}
```

### Subscription Lifecycle Events

**`subscription.created`** - New subscription started

**`subscription.updated`** - Subscription modified (upgrade, downgrade, etc.)

**`subscription.trial_ending`** - Trial period ending soon (3 days before)

**`subscription.trial_ended`** - Trial period ended

**`subscription.renewed`** - Subscription renewed for new period

**`subscription.canceled`** - Subscription canceled

**`subscription.expired`** - Subscription expired without renewal

### Payment Events

**`invoice.created`** - New invoice generated

**`invoice.paid`** - Invoice paid successfully

**`invoice.payment_failed`** - Payment failed

**`payment.succeeded`** - Payment processed successfully

**`payment.failed`** - Payment failed

### Usage Events

**`customer.threshold_reached`** - Customer hit usage threshold

```json
{
  "type": "customer.threshold_reached",
  "data": {
    "customer_id": "customer_123",
    "feature": {
      "id": "api_calls",
      "name": "API Calls"
    },
    "threshold": 90,
    "current_usage": 9000,
    "limit": 10000
  }
}
```

## Event Handling Patterns

### Provisioning Access

Grant access when customers subscribe:

```typescript
async function handleWebhookEvent(event) {
  switch (event.type) {
    case "customer.product.created":
      if (event.data.scenario === "subscription_started") {
        await provisionAccess({
          customerId: event.data.customer_id,
          productId: event.data.product_id
        });
      }
      break;
  }
}

async function provisionAccess({ customerId, productId }) {
  // Enable features in your system
  await db.users.update(
    { autumnCustomerId: customerId },
    { plan: productId, accessGranted: true }
  );

  // Send welcome email
  await sendEmail({
    to: user.email,
    subject: "Welcome to Pro!",
    template: "subscription_started"
  });
}
```

### Revoking Access

Remove access when subscriptions end:

```typescript
case "customer.product.deleted":
  if (event.data.status === "canceled") {
    await revokeAccess({
      customerId: event.data.customer_id,
      productId: event.data.product_id
    });
  }
  break;

async function revokeAccess({ customerId, productId }) {
  // Disable features
  await db.users.update(
    { autumnCustomerId: customerId },
    { plan: "free", accessGranted: false }
  );

  // Send cancellation email
  await sendEmail({
    to: user.email,
    subject: "Subscription Canceled",
    template: "subscription_canceled"
  });
}
```

### Handling Failed Payments

Notify customers and prevent access loss:

```typescript
case "invoice.payment_failed":
  const customer = await getCustomer(event.data.customer_id);
  
  // Send payment failure email
  await sendEmail({
    to: customer.email,
    subject: "Payment Failed - Action Required",
    template: "payment_failed",
    data: {
      amount: event.data.amount,
      retryDate: event.data.next_retry
    }
  });

  // Set grace period (don't revoke immediately)
  await db.users.update(
    { autumnCustomerId: event.data.customer_id },
    { paymentStatus: "past_due", gracePeriodEnd: addDays(new Date(), 3) }
  );
  break;
```

### Usage Alerts

Notify customers when approaching limits:

```typescript
case "customer.threshold_reached":
  const { customer_id, feature, threshold, current_usage, limit } = event.data;
  
  await sendEmail({
    to: customer.email,
    subject: `${threshold}% of ${feature.name} limit reached`,
    template: "usage_threshold",
    data: {
      feature: feature.name,
      used: current_usage,
      limit: limit,
      remaining: limit - current_usage,
      upgradeUrl: `https://yourapp.com/upgrade`
    }
  });
  break;
```

## Webhook Verification

Always verify webhook signatures to ensure requests are from Autumn:

```typescript
import { Webhook } from "svix";

function verifyWebhook(rawBody, headers) {
  const wh = new Webhook(process.env.AUTUMN_WEBHOOK_SECRET);
  
  try {
    const event = wh.verify(rawBody, {
      "svix-id": headers["svix-id"],
      "svix-timestamp": headers["svix-timestamp"],
      "svix-signature": headers["svix-signature"]
    });
    return event;
  } catch (err) {
    throw new Error("Invalid webhook signature");
  }
}
```

<Warning>
Never process unverified webhooks. Attackers could send fake events to manipulate your system.
</Warning>

## Retry Logic

If your endpoint returns an error or times out, Autumn automatically retries:

- Immediate retry
- After 5 minutes
- After 15 minutes
- After 1 hour
- After 3 hours
- After 6 hours

Return a 2xx status code to acknowledge receipt and stop retries.

```typescript
app.post("/webhooks/autumn", async (req, res) => {
  try {
    const event = verifyWebhook(req.body, req.headers);
    
    // Process asynchronously
    processWebhookAsync(event).catch(console.error);
    
    // Acknowledge immediately
    return res.status(200).json({ received: true });
  } catch (err) {
    // Return 200 even if processing fails to stop retries
    console.error("Webhook processing error:", err);
    return res.status(200).json({ error: err.message });
  }
});
```

<Tip>
Respond quickly (< 3 seconds) to acknowledge the webhook, then process events asynchronously to avoid timeouts.
</Tip>

## Idempotency

Webhooks may be delivered more than once. Make your handlers idempotent:

```typescript
async function handleWebhookEvent(event) {
  // Check if already processed
  const existing = await db.webhookEvents.findOne({
    eventId: event.id
  });

  if (existing) {
    console.log("Event already processed:", event.id);
    return;
  }

  // Process event
  await processEvent(event);

  // Mark as processed
  await db.webhookEvents.insert({
    eventId: event.id,
    type: event.type,
    processedAt: new Date()
  });
}
```

```bash
    }
  }'
```

## Monitoring Webhooks

Track webhook delivery in the Autumn dashboard:

- Delivery status (success/failure)
- Response times
- Error messages
- Retry attempts
- Event payload

Set up alerts for:
- High failure rate
- Slow response times
- Consecutive failures

## Best Practices

<Card title="Respond quickly" icon="bolt">
  Return 200 OK within 3 seconds. Process events asynchronously to avoid timeouts.
</Card>

<Card title="Verify signatures" icon="shield">
  Always verify webhook signatures before processing. Never trust unverified requests.
</Card>

<Card title="Handle duplicates" icon="copy">
  Implement idempotency using event IDs to safely handle duplicate deliveries.
</Card>

<Card title="Log everything" icon="file">
  Log all webhook events, processing results, and errors for debugging and auditing.
</Card>

<Card title="Handle errors gracefully" icon="triangle-exclamation">
  Return 200 even if processing fails. Use a dead letter queue for failed events.
</Card>

<Card title="Monitor delivery" icon="chart-line">
  Set up alerts for webhook failures. Check the dashboard regularly for delivery issues.
</Card>

<Card title="Version your handlers" icon="code-branch">
  Support multiple webhook versions to avoid breaking changes when updating your endpoint.
</Card>
