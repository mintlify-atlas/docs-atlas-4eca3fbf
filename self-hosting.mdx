This guide covers how to self-host Autumn in your own environment. Autumn is fully open-source and can be deployed on any infrastructure that supports Docker and PostgreSQL.

<Note>
  **Prefer Managed Hosting?** Use [Autumn Cloud](https://app.useautumn.com) for a fully managed, production-ready service with zero setup.
</Note>

## Prerequisites

<CardGroup cols={2}>
  <Card title="Bun Runtime" icon="package">

  <Card title="Docker" icon="docker">

## Quick Start (Local Development)

<Steps>
  <Step title="Clone the Repository">
    ```bash
    git clone https://github.com/useautumn/autumn.git
    cd autumn
    ```
  </Step>

  <Step title="Install Dependencies">
    ```bash
    bun install
    ```

    <Note>
      Autumn uses **Bun** as its package manager and runtime. The setup script requires Bun to be installed.
    </Note>
  </Step>

  <Step title="Run Setup Script">
    ```bash
    bun setup
    ```

    This interactive script will:
    - Generate secure environment variables (auth secrets, encryption keys)
    - Set up a local tunnel for Stripe webhooks
    - Optionally create a Supabase database instance
    - Configure environment files

    <Accordion title="Setup Script Output">
      The script generates:
      - `BETTER_AUTH_SECRET` — Authentication secret
      - `ENCRYPTION_IV` and `ENCRYPTION_PASSWORD` — For encrypting Stripe credentials
      - `LOCALTUNNEL_RESERVED_KEY` — For Stripe webhook delivery
      - `STRIPE_WEBHOOK_URL` — Public URL for webhooks
    </Accordion>
  </Step>

  <Step title="Configure Database">
    You have three options:

    <Tabs>
      <Tab title="Supabase (Recommended)">
        The setup script can create a free Supabase database automatically:

        1. Select **"Set up Supabase (Cloud) for Autumn"**
        2. Follow the prompts to authenticate
        3. The script will create a project and configure the `DATABASE_URL`

        The generated URL will look like:
        ```bash
        DATABASE_URL=postgresql://postgres.xxxxx:password@aws-1-region.pooler.supabase.com:5432/postgres
        ```
      </Tab>

      <Tab title="Your Own PostgreSQL">
        If you have an existing PostgreSQL instance:

        1. Create a database: `CREATE DATABASE autumn;`
        2. Add the connection string to `server/.env`:

        ```bash
        DATABASE_URL=postgresql://user:password@localhost:5432/autumn
        ```
      </Tab>

      <Tab title="Configure Later">
        Skip database setup and add it later to `server/.env`
      </Tab>
    </Tabs>
  </Step>

  <Step title="Generate Database Schema">
    ```bash
    bun db:generate && bun db:migrate
    ```

    This creates all required tables, indexes, and functions in your PostgreSQL database.

    <Tip>
      If you encounter a `SyntaxError: Unexpected end of JSON input` error, you may need to clear your database tables first. This is a [known issue](https://github.com/drizzle-team/drizzle-orm/issues/4529) when running migrations multiple times.
    </Tip>
  </Step>

  <Step title="Start Autumn">
    <Tabs>
      <Tab title="macOS/Linux">
        ```bash
        docker compose -f docker-compose.unix.yml up
        ```
      </Tab>

      <Tab title="Windows">
        ```bash
        docker compose -f docker-compose.dev.yml up
        ```
      </Tab>
    </Tabs>

    This starts:
    - **Vite frontend** on `http://localhost:3000`
    - **API server** on `http://localhost:8080`
    - **Valkey (Redis)** on `localhost:6379`
    - **BullMQ workers** for background jobs
    - **Localtunnel** for webhook delivery
  </Step>

  <Step title="Access the Dashboard">
    Open [http://localhost:3000](http://localhost:3000)

    <Warning>
      **Authentication Note**: Enter any email at the sign-in page. The OTP will appear in your terminal/console logs (not sent via email in development mode).

      To enable real email delivery, configure [Resend](#optional-email-with-resend) in your `.env` file.
    </Warning>
  </Step>
</Steps>

## Environment Variables

### Required Variables

These are automatically generated by `bun setup`:

```bash server/.env
# Authentication
BETTER_AUTH_SECRET=<generated>
BETTER_AUTH_URL=http://localhost:8080
CLIENT_URL=http://localhost:3000

# Stripe Encryption
ENCRYPTION_IV=<generated>
ENCRYPTION_PASSWORD=<generated>

# Stripe Webhooks
STRIPE_WEBHOOK_URL=<generated>
LOCALTUNNEL_RESERVED_KEY=<generated>

# Database
DATABASE_URL=postgresql://...

# Redis (optional but recommended)
REDIS_URL=redis://localhost:6379
```

```bash vite/.env
VITE_FRONTEND_URL=http://localhost:3000
VITE_BACKEND_URL=http://localhost:8080
```

### Optional Variables

<AccordionGroup>
  <Accordion title="Google OAuth" icon="google">
    Enable Google sign-in:

    ```bash
    GOOGLE_CLIENT_ID=your-client-id
    GOOGLE_CLIENT_SECRET=your-client-secret
    ```

    Get these from [Google Cloud Console](https://console.cloud.google.com/apis/credentials).
  </Accordion>

  <Accordion title="Email with Resend" icon="envelope">
    Send OTP emails and transactional messages:

    ```bash
    RESEND_API_KEY=re_...
    RESEND_DOMAIN=yourdomain.com
    ```

    Sign up at [resend.com](https://resend.com) for a free API key.
  </Accordion>

  <Accordion title="Webhooks with Svix" icon="webhook">
    Enable webhook delivery to your users:

    ```bash
    SVIX_API_KEY=sk_...
    ```

    Get an API key at [svix.com](https://www.svix.com).
  </Accordion>

  <Accordion title="Usage Analytics with ClickHouse" icon="chart-line">
    Store usage events for analytics:

    ```bash
    CLICKHOUSE_URL=https://your-instance.clickhouse.cloud
    CLICKHOUSE_USERNAME=default
    CLICKHOUSE_PASSWORD=...
    CLICKHOUSE_SKIP_ENSURES=false  # Set to true after first run
    ```
  </Accordion>

  <Accordion title="Logging with Axiom" icon="file-lines">
    Send structured logs to Axiom:

    ```bash
    AXIOM_TOKEN=xaat-...
    ```
  </Accordion>

  <Accordion title="AI Features with Anthropic" icon="robot">
    Generate singular/plural feature names:

    ```bash
    ANTHROPIC_API_KEY=sk-ant-...
    ```
  </Accordion>
</AccordionGroup>

## Production Deployment

### Docker Deployment

<Steps>
  <Step title="Build the Docker Image">
    ```bash
    docker build -f docker/Dockerfile -t autumn:latest .
    ```

    The Dockerfile:
    - Uses `oven/bun:1.3.2` as base image
    - Installs all workspace dependencies
    - Exposes port 8080 for the API server
  </Step>

  <Step title="Run the Container">
    ```bash
    docker run -p 8080:8080 \
      -e DATABASE_URL="postgresql://..." \
      -e REDIS_URL="redis://..." \
      -e BETTER_AUTH_SECRET="..." \
      -e ENCRYPTION_IV="..." \
      -e ENCRYPTION_PASSWORD="..." \
      autumn:latest
    ```
  </Step>

  <Step title="Run Workers (Optional but Recommended)">
    Start background workers for async tasks:

    ```bash
    docker run \
      -e DATABASE_URL="postgresql://..." \
      -e REDIS_URL="redis://..." \
      autumn:latest \
      bun workers
    ```
  </Step>
</Steps>

### Database Migrations

When deploying updates, run migrations:

```bash
bun db:generate && bun db:migrate
```

Or in Docker:

```bash
docker exec autumn-server bun -F @autumn/shared db:migrate
```

## Configuration for Production

<Warning>
  **Security Checklist**:
  - Use strong, unique secrets for `BETTER_AUTH_SECRET`
  - Store all credentials in a secret manager (not in code)
  - Enable HTTPS/TLS for all public endpoints
  - Use connection pooling for PostgreSQL (e.g., Supabase Pooler)
  - Restrict database access to your application's IP
  - Enable Redis authentication if exposed
</Warning>

### Recommended Stack

- **Database**: Supabase, AWS RDS, or any managed PostgreSQL
- **Redis**: Upstash, AWS ElastiCache, or self-hosted Valkey
- **Container Orchestration**: Kubernetes, AWS ECS, or Railway
- **Monitoring**: Sentry, Axiom, or your preferred logging service

### Stripe Webhooks

For production, configure a real webhook endpoint:

1. Deploy your API server to a public URL
2. In Stripe Dashboard → **Developers** → **Webhooks**, add:
   ```
   https://your-domain.com/webhooks/stripe
   ```
3. Update `server/.env`:
   ```bash
   STRIPE_WEBHOOK_URL=https://your-domain.com/webhooks/stripe
   ```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Database Migration Errors">
    If you see `SyntaxError: Unexpected end of JSON input`:

    1. Connect to your database
    2. Drop all tables: `DROP SCHEMA public CASCADE; CREATE SCHEMA public;`
    3. Run migrations again: `bun db:generate && bun db:migrate`

    This is a [known Drizzle issue](https://github.com/drizzle-team/drizzle-orm/issues/4529).
  </Accordion>

  <Accordion title="Localtunnel Connection Issues">
    If Stripe webhooks aren't being delivered locally:

    1. Check that localtunnel service is running in Docker logs
    2. Verify `LOCALTUNNEL_RESERVED_KEY` matches in `.env`
    3. Test the tunnel URL manually in your browser
  </Accordion>

  <Accordion title="Port Conflicts">
    If ports 3000 or 8080 are in use:

    1. Stop the conflicting services
    2. Or modify port mappings in `docker-compose.*.yml`
  </Accordion>

  <Accordion title="Authentication Issues">
    If you can't sign in:

    1. Check console logs for the OTP code
    2. Verify `BETTER_AUTH_SECRET` is set
    3. Ensure `BETTER_AUTH_URL` and `CLIENT_URL` match your deployment URLs
  </Accordion>
</AccordionGroup>

## Updating Autumn

To update to the latest version:

```bash
git pull origin main
bun install
bun db:generate && bun db:migrate
docker compose -f docker-compose.unix.yml up --build
```
