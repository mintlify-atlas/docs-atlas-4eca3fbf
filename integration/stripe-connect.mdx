Stripe Connect enables Autumn to process payments on behalf of connected accounts. This is the recommended approach for production deployments and multi-tenant platforms.

## Overview

Autumn's Stripe Connect integration allows:

- Users to connect their Stripe accounts via OAuth
- Platform to process payments on connected accounts
- Automatic account management and token refresh
- Secure credential handling (credentials never stored)

## Architecture

### Master and Connected Accounts

Autumn uses a dual-account model:

**Master Account**
- Your platform's main Stripe account
- Configured with `STRIPE_LIVE_SECRET_KEY` / `STRIPE_SANDBOX_SECRET_KEY`
- Used to manage connected accounts
- Receives platform webhooks

**Connected Accounts**
- Your customers' Stripe accounts
- Linked via OAuth or created as platform-managed accounts
- Each organization can have one connected account per environment
- Identified by `account_id` in the database

## OAuth Flow

<Steps>
  <Step title="User Initiates Connection">
    User clicks "Connect with Stripe" in the Autumn dashboard.
    
    ```typescript
    // Generated OAuth URL
    server/src/internal/orgs/handlers/stripeHandlers/handleGetOAuthUrl.ts:6
    ```
    
    The OAuth URL includes:
    - Client ID for your environment (test/live)
    - Redirect URI back to your server
    - State parameter for security
  </Step>

  <Step title="User Authorizes on Stripe">
    User is redirected to Stripe's OAuth consent page where they:
    - Log in to their Stripe account
    - Grant permissions to your platform
    - Authorize the connection
  </Step>

  <Step title="Autumn Receives Callback">
    Stripe redirects back to your server with an authorization code:
    
    ```
    POST /stripe/oauth_callback
    ```
    
    Autumn:
    1. Verifies the state parameter
    2. Exchanges authorization code for account credentials
    3. Stores the `account_id` in the database
    4. Redirects user back to dashboard
  </Step>
</Steps>

## Making API Calls on Connected Accounts

Autumn automatically routes API calls to the correct account:

```typescript
// Creating a Stripe client for an organization
import { createStripeCli } from '@/external/connect/createStripeCli';

const stripeCli = createStripeCli({ org, env });

// All calls are automatically scoped to the connected account
const customer = await stripeCli.customers.create({
  email: 'customer@example.com'
});
```

## Webhook Handling for Connect

Connect webhooks are sent to a platform-level endpoint:

```
POST /webhooks/connect/:env
```

### Webhook Flow

<Steps>
  <Step title="Webhook Received">
    Stripe sends webhook to your Connect endpoint with:
    - Event data
    - `account` field identifying the connected account
    - Signature for verification
  </Step>

  <Step title="Signature Verification">

    1. Gets master Stripe client
    2. Retrieves webhook secret from environment

  </Step>

  <Step title="Account Resolution">

    1. Extracts `account_id` from webhook event
    2. Looks up organization by account ID
    3. Loads organization features

  <Step title="Event Processing">

  </Step>
</Steps>

## Account Management

### Getting Account ID

```typescript
import { orgToAccountId } from '@/external/connect/connectUtils';

const accountId = orgToAccountId({ 
  org, 
  env: AppEnv.Live,
  noDefaultAccount: false // Whether to exclude default account
});
```

### Checking Connection Status

```typescript
import { isStripeConnected } from '@/internal/orgs/orgUtils';

// Check any connection (OAuth or secret key)
const connected = isStripeConnected({ org, env });

// Check specifically for OAuth connection
const oauthConnected = isStripeConnected({ 
  org, 
  env,
  throughAccountId: true 
});
```

### Disconnecting Accounts

```typescript
import { deauthorizeAccount, deleteConnectedAccount } from '@/external/connect/connectUtils';

// For OAuth-connected accounts (recommended)
await deauthorizeAccount({ accountId, env, logger });

// For platform-managed accounts
await deleteConnectedAccount({ accountId, env, logger });
```

## Master Organization Pattern

Autumn supports a "master organization" pattern for platform operators:

```typescript
const useMaster = shouldUseMaster({ org, env });
```

When enabled:
- The organization has a `master_org_id` set
- API calls route through the master org's Stripe account
- Connected account is used as the `stripeAccount` parameter
- Useful for revenue share or platform fee models

## OAuth Configuration

### Redirect URI

The OAuth callback URL must be configured in your Stripe Connect settings:

```
# For production
https://your-domain.com/stripe/oauth_callback

# For development
http://localhost:8080/stripe/oauth_callback
```

### State Parameter

Autumn generates and validates OAuth state for security:

```typescript
server/src/internal/platform/platformBeta/utils/oauthStateUtils.ts
```

State includes:
- Organization slug
- Environment (test/live)
- Redirect URI after connection
- Master org ID (if applicable)

## Best Practices

<AccordionGroup>
  <Accordion title="Use OAuth in Production">
    OAuth is more secure and provides a better user experience than secret key connections. Always use OAuth for production deployments.
  </Accordion>

  <Accordion title="Handle Account Disconnections">
    Users can disconnect their Stripe accounts at any time through the Stripe dashboard. Implement proper error handling for missing accounts.
  </Accordion>

  <Accordion title="Test Both Modes">
    Always test your integration in both sandbox and live modes. Each has separate credentials and connected accounts.
  </Accordion>

  <Accordion title="Monitor Webhook Failures">
    Connect webhooks include an `account` field. Ensure you're properly routing events to the correct organization.
  </Accordion>
</AccordionGroup>

## Troubleshooting

### "Master organization not found" Error

This occurs when:
- An org has `master_org_id` set but the master org doesn't exist
- The master org relationship is misconfigured

**Solution:** Verify the `master` relationship is properly loaded from the database.

### "Connect webhook secret not found" Error

Connect webhooks require webhook secrets stored in the database:

```typescript
org.stripe_config.test_connect_webhook_secret
org.stripe_config.live_connect_webhook_secret
```

**Solution:** Ensure webhook secrets are configured in your environment.

### "Account ID not linked to any org" Warning

This means a webhook was received for an account ID that doesn't exist in your database.

**Possible causes:**
- Account was disconnected but webhooks are still firing
- Database and Stripe are out of sync
- Webhook is for a different platform/environment
