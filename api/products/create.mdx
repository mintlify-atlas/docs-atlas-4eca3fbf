---
title: "Create Product"
api: "POST /products"
---

Creates a new product with pricing and features. Products define what customers can purchase, including subscription plans, usage-based pricing, and feature access.

## Product Structure

A product consists of:
- **Base price**: A fixed recurring or one-time charge
- **Product items**: Features with usage limits and optional pricing
- **Free trial**: Optional trial period configuration

## Product Types

### Standard Products
Products that customers can switch between through upgrade/downgrade flows. Products in the same `group` can be upgraded/downgraded between.

### Add-on Products
Products that can be purchased alongside other products. Set `is_add_on: true` to enable this behavior.

### Default Products
Products that are automatically enabled for new customers. Set `is_default: true` to make a product default.

## Request Body

<ParamField body="id" type="string" required>
  The ID of the product. Used to identify the product in other API calls like checkout or update product. Must match the pattern: alphanumeric, hyphens, and underscores only.
  
  <Expandable title="Example">
  ```
  "pro-plan"
  ```
  </Expandable>
</ParamField>

<ParamField body="name" type="string" required>
  The display name of the product.
  
  <Expandable title="Example">
  ```
  "Pro Plan"
  ```
  </Expandable>
</ParamField>

<ParamField body="description" type="string">
  Optional description of the product.
</ParamField>

<ParamField body="is_add_on" type="boolean" default={false}>
  Whether the product is an add-on. Add-on products can be attached multiple times and don't go through upgrade/downgrade flows.
</ParamField>

<ParamField body="is_default" type="boolean" default={false}>
  Whether the product is the default product. Default products are enabled by default for new customers.
</ParamField>

<ParamField body="group" type="string">
  Product group which this product belongs to. Products within a group have upgrade/downgrade logic when customers move between them.
</ParamField>

<ParamField body="items" type="array">
  Array of product items that define the product's features and pricing. Each item can be:
  - **Price**: A fixed recurring or one-time charge
  - **Feature**: A feature with usage limits
  - **Priced Feature**: A feature with usage limits and overage pricing
  
  <Expandable title="Item Structure">
  
  <ParamField body="items[].feature_id" type="string">
    The ID of the feature to include. Set to `null` for fixed price items.
  </ParamField>
  
  <ParamField body="items[].price" type="number">
    The price amount for this item.
  </ParamField>
  
  <ParamField body="items[].tiers" type="array">
    Tiered pricing configuration. Cannot be used with `price`.
    
    Each tier has:
    - `to`: Maximum usage for this tier (use `"inf"` for unlimited)
    - `amount`: Price for this tier
  </ParamField>
  
  <ParamField body="items[].interval" type="string">
    Billing or reset interval: `day`, `week`, `month`, `year`, or `one_time`.
  </ParamField>
  
  <ParamField body="items[].interval_count" type="number" default={1}>
    Number of intervals between billing/reset cycles.
  </ParamField>
  
  <ParamField body="items[].included_usage" type="number">
    Amount of usage included for this feature.
  </ParamField>
  
  <ParamField body="items[].unlimited" type="boolean">
    Whether the feature provides unlimited usage.
  </ParamField>
  
  <ParamField body="items[].usage_model" type="string">
    How the feature is billed:
    - `prepaid`: Customer pays upfront for capacity
    - `pay_per_use`: Customer is billed based on actual usage
  </ParamField>
  
  <ParamField body="items[].billing_units" type="number" default={1}>
    The amount per billing unit (e.g., $0.5 per 1,000 units).
  </ParamField>
  
  <ParamField body="items[].reset" type="object">
    Reset configuration for usage limits.
    
    - `interval`: Reset interval (`day`, `week`, `month`, `year`)
    - `interval_count`: Number of intervals between resets
  </ParamField>
  
  <ParamField body="items[].proration" type="object">
    Proration behavior when customer changes quantity.
    
    - `on_increase`: How to handle increases (`prorate_immediately`, `apply_next_cycle`)
    - `on_decrease`: How to handle decreases (`prorate_immediately`, `apply_next_cycle`)
  </ParamField>
  
  <ParamField body="items[].rollover" type="object">
    Rollover configuration for unused usage.
    
    - `max`: Maximum amount that can rollover
    - `expiry_duration_type`: When rollover expires (`month`, `year`, `never`)
    - `expiry_duration_length`: Length before expiry
  </ParamField>
  
  </Expandable>
</ParamField>

<ParamField body="free_trial" type="object">
  Free trial configuration for this product.
  
  <Expandable title="Free Trial Structure">
  
  <ParamField body="free_trial.duration" type="string" required>
    The duration type: `day`, `week`, `month`, or `year`.
  </ParamField>
  
  <ParamField body="free_trial.length" type="number" required>
    The length of the duration type (e.g., `7` for 7 days).
  </ParamField>
  
  <ParamField body="free_trial.unique_fingerprint" type="boolean" required>
    Whether the trial is limited to one per customer fingerprint.
  </ParamField>
  
  <ParamField body="free_trial.card_required" type="boolean" required>
    Whether a payment method is required to start the trial.
  </ParamField>
  
  </Expandable>
</ParamField>

## Common Examples

### Simple Subscription Product

A basic monthly subscription with no usage limits:

```json
{
  "id": "basic-monthly",
  "name": "Basic Plan",
  "items": [
    {
      "price": 10,
      "interval": "month"
    },
    {
      "feature_id": "dashboard",
      "unlimited": true
    }
  ]
}
```

### Usage-Based Product

A product with pay-per-use pricing:

```json
{
  "id": "pay-as-you-go",
  "name": "Pay As You Go",
  "items": [
    {
      "feature_id": "storage-gb",
      "included_usage": 10,
      "price": 5,
      "interval": "month",
      "usage_model": "pay_per_use",
      "billing_units": 1
    }
  ]
}
```

### Tiered Pricing Product

A product with volume-based tiered pricing:

```json
{
  "id": "tiered-plan",
  "name": "Tiered Plan",
  "items": [
    {
      "price": 50,
      "interval": "month"
    },
    {
      "feature_id": "api-calls",
      "tiers": [
        { "to": 1000, "amount": 0 },
        { "to": 10000, "amount": 0.01 },
        { "to": "inf", "amount": 0.005 }
      ],
      "interval": "month",
      "usage_model": "pay_per_use",
      "billing_units": 1
    }
  ]
}
```

### Add-on Product

An add-on that can be purchased alongside other products:

```json
{
  "id": "extra-storage",
  "name": "Extra Storage",
  "is_add_on": true,
  "items": [
    {
      "feature_id": "storage-gb",
      "included_usage": 100,
      "price": 15,
      "interval": "month"
    }
  ]
}
```

### Prepaid Feature Product

A product where customers prepay for capacity:

```json
{
  "id": "prepaid-messages",
  "name": "Message Bundle",
  "items": [
    {
      "feature_id": "messages",
      "included_usage": 1000,
      "price": 10,
      "interval": "one_time",
      "usage_model": "prepaid"
    }
  ]
}
```

## Notes

- Product IDs must be unique within your organization and environment
- You cannot create a product with the same ID as an existing product
- Items can specify either `price` or `tiers`, but not both
- Features must be created before being referenced in product items
- Free trials are only available for products with recurring prices
- Once customers are attached to a product, updating pricing/features creates a new version
