---
title: "Update Product"
api: "POST /products/{product_id}"
---

Updates an existing product's configuration, pricing, or features. How updates are handled depends on whether the product has active customers.

## Path Parameters

<ParamField path="product_id" type="string" required>
  The ID of the product to update.
</ParamField>

## Query Parameters

<ParamField query="version" type="number">
  Specific version of the product to update. If not provided, updates the latest version.
</ParamField>

<ParamField query="upsert" type="boolean" default={false}>
  If `true`, creates the product if it doesn't exist.
</ParamField>

<ParamField query="disable_version" type="boolean" default={false}>
  If `true`, prevents automatic versioning even when customers exist. This will cause an error if customers exist and pricing/features are changed.
</ParamField>

## Request Body

All fields are optional. Only include fields you want to update.

<ParamField body="id" type="string">
  New ID for the product. Use with caution as this changes how you reference the product.
</ParamField>

<ParamField body="name" type="string">
  New name for the product.
</ParamField>

<ParamField body="description" type="string">
  New description for the product. Set to `null` to remove.
</ParamField>

<ParamField body="is_add_on" type="boolean">
  Change whether the product is an add-on.
</ParamField>

<ParamField body="is_default" type="boolean">
  Change whether the product is a default product.
</ParamField>

<ParamField body="group" type="string">
  Change the product group. Set to empty string to remove from group.
</ParamField>

<ParamField body="archived" type="boolean">
  Archive or unarchive the product. Archived products are hidden and not available for new purchases.
</ParamField>

<ParamField body="items" type="array">
  New array of product items. This completely replaces the existing items.
  
  See [Create Product](/api/products/create#request-body) for the structure of product items.
</ParamField>

<ParamField body="free_trial" type="object">
  Update the free trial configuration. Set to `null` to remove the free trial.
  
  See [Create Product](/api/products/create#request-body) for the structure of free trial objects.
</ParamField>

## Update Behavior

### Products Without Customers

When a product has no active or expired customers:
- Updates are applied directly to the product
- No versioning occurs
- Changes take effect immediately for new customers

### Products With Customers

When a product has customers and you update `items` or `free_trial`:
- **Automatic versioning**: A new version is created automatically
- **Existing customers**: Remain on their current version
- **New customers**: Get the new version by default
- **Version number**: Increments (v1 → v2)

Example: You have a product with `version: 1` and 50 customers. You update the pricing:
1. A new `version: 2` is created with the new pricing
2. Existing 50 customers stay on version 1
3. New customers get version 2
4. The response returns the version 2 product

### Detail-Only Updates

Updating only `name`, `description`, `group`, `is_add_on`, `is_default`, or `archived`:
- Does NOT create a new version
- Updates apply to the current version immediately
- All customers see the updated details

## Common Update Scenarios

### Update Product Name

```json
{
  "name": "Premium Plan"
}
```

No versioning occurs, change is immediate.

### Archive a Product

```json
{
  "archived": true
}
```

Prevents new customers from purchasing, existing customers unaffected.

### Change Pricing

```json
{
  "items": [
    {
      "price": 30,
      "interval": "month"
    }
  ]
}
```

Creates new version if customers exist. Existing customers keep their current price.

### Add New Feature

```json
{
  "items": [
    {
      "price": 20,
      "interval": "month"
    },
    {
      "feature_id": "api-calls",
      "included_usage": 10000,
      "price": 0.001,
      "interval": "month",
      "usage_model": "pay_per_use",
      "billing_units": 1000
    },
    {
      "feature_id": "new-feature",
      "unlimited": true
    }
  ]
}
```

Creates new version if customers exist. Must include ALL items, not just the new one.

### Remove Free Trial

```json
{
  "free_trial": null
}
```

Creates new version if customers exist. Existing customers' trials are unaffected.

### Update Without Versioning

```json
{
  "items": [...]
}
```

With query parameter `?disable_version=true`. This will throw an error if customers exist.

## Notes

- When updating `items`, you must provide the complete array of items, not just changes
- You cannot update a product that doesn't exist (unless `upsert=true`)
- Changing `is_default` to `true` will unset other default products in the same group
- Product ID changes should be done carefully as they affect API references
- Versioning protects existing customers from unexpected pricing changes
- To migrate customers between versions, use the [Migrations API](/api/migrations/create)
