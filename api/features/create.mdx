## Overview

Create a new feature to track usage, enforce limits, and enable usage-based billing. Features define what can be metered in your application - API calls, storage, credits, seats, or any custom resource.

## Endpoint

```
POST /features
```

## Authentication

This endpoint requires authentication. Include your API key in the `Authorization` header:

```
Authorization: Bearer YOUR_API_KEY
```

## Request

### Body Parameters

<ParamField body="id" type="string" required>
  Unique identifier for the feature (e.g., `api-calls`, `storage`, `credits`). Used to reference this feature in other API calls like `/track` or `/check`.
  
  Must match the pattern: lowercase letters, numbers, hyphens, and underscores only.
</ParamField>

<ParamField body="name" type="string">
  Human-readable name for the feature (e.g., "API Calls", "Storage", "Credits").
</ParamField>

<ParamField body="type" type="enum" required>
  The type of feature to create:
  
  - `metered` - Track consumable or continuous usage (API calls, storage, seats)
  - `credit_system` - Universal currency that converts to metered features
  - `boolean` - Simple on/off feature flag
  
  See [Feature Types](/concepts/features#feature-types) for details.
</ParamField>

<ParamField body="consumable" type="boolean">
  **Required for metered features.** Specifies whether the feature is consumed or allocated:
  
  - `true` - Consumable (e.g., API tokens, credits, messages) - usage accumulates
  - `false` - Allocated (e.g., seats, workspaces, projects) - usage is a snapshot
  
  Not applicable for `boolean` or `credit_system` types.
</ParamField>

<ParamField body="credit_schema" type="array">
  **Required for credit_system features.** Defines conversion rates from credits to metered features.
  
  <Expandable title="Credit Schema Item">
    <ParamField body="metered_feature_id" type="string" required>
      ID of the metered feature that can be purchased with credits.
    </ParamField>
    
    <ParamField body="credit_cost" type="number" required>
      Number of credits required per unit of the metered feature.
    </ParamField>
  </Expandable>
  
  Example:
  ```json
  [
    {
      "metered_feature_id": "api-calls",
      "credit_cost": 1
    },
    {
      "metered_feature_id": "storage-gb",
      "credit_cost": 100
    }
  ]
  ```
</ParamField>

<ParamField body="display" type="object">
  Display names for proper pluralization in your UI.
  
  <Expandable title="properties">
    <ParamField body="singular" type="string">
      Singular form (e.g., "API Call", "Credit", "Seat").
    </ParamField>
    
    <ParamField body="plural" type="string">
      Plural form (e.g., "API Calls", "Credits", "Seats").
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="event_names" type="array">
  Optional array of event names that contribute to this feature's usage tracking. When specified, only events with these names will increment usage for this feature.
  
  Example: `["api_call", "api_request"]`
</ParamField>

## Response

### Success Response (200)

Returns the created feature object.

<ResponseField name="id" type="string">
  The unique identifier for the feature.
</ResponseField>

<ResponseField name="name" type="string">
  The human-readable name of the feature.
</ResponseField>

<ResponseField name="type" type="enum">
  The feature type: `metered`, `credit_system`, or `boolean`.
</ResponseField>

<ResponseField name="consumable" type="boolean">
  Whether the feature is consumable (true) or allocated (false). Only present for metered features.
</ResponseField>

<ResponseField name="credit_schema" type="array">
  Credit conversion schema. Only present for credit_system features.
</ResponseField>

<ResponseField name="display" type="object">
  Display names for the feature.
  
  <Expandable title="properties">
    <ResponseField name="singular" type="string">
      Singular display name.
    </ResponseField>
    
    <ResponseField name="plural" type="string">
      Plural display name.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="event_names" type="array">
  Array of event names that trigger this feature's usage tracking.
</ResponseField>

<ResponseField name="archived" type="boolean">
  Whether the feature is archived. Always `false` for newly created features.
</ResponseField>

## Examples

### Metered Feature (Consumable)

Create a feature for tracking API call usage:

<CodeGroup>

```bash cURL
curl -X POST https://api.autumnhq.com/v1/features \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "api-calls",
    "name": "API Calls",
    "type": "metered",
    "consumable": true,
    "display": {
      "singular": "API Call",
      "plural": "API Calls"
    },
    "event_names": ["api_call"]
  }'
```

```typescript TypeScript
import { AutumnClient } from '@useautumn/autumn-js';

const autumn = new AutumnClient({
  apiKey: 'YOUR_API_KEY'
});

const feature = await autumn.features.create({
  id: 'api-calls',
  name: 'API Calls',
  type: 'metered',
  consumable: true,
  display: {
    singular: 'API Call',
    plural: 'API Calls'
  },
  event_names: ['api_call']
});

console.log(`Feature created: ${feature.id}`);
```

```python Python
from autumn import AutumnClient

autumn = AutumnClient(api_key='YOUR_API_KEY')

feature = autumn.features.create(
    id='api-calls',
    name='API Calls',
    type='metered',
    consumable=True,
    display={
        'singular': 'API Call',
        'plural': 'API Calls'
    },
    event_names=['api_call']
)

print(f"Feature created: {feature['id']}")
```

</CodeGroup>

### Response

```json
{
  "id": "api-calls",
  "name": "API Calls",
  "type": "metered",
  "consumable": true,
  "display": {
    "singular": "API Call",
    "plural": "API Calls"
  },
  "event_names": ["api_call"],
  "archived": false
}
```

## Error Handling

### Common Errors

- **400 Bad Request**: Invalid request parameters
  - Missing required fields (`id`, `type`)
  - Invalid `id` format (must be lowercase with hyphens/underscores)
  - Missing `consumable` for metered features
  - Missing `credit_schema` for credit_system features
  - Credit system features must be consumable
- **401 Unauthorized**: Invalid or missing API key
- **409 Conflict**: Feature with this ID already exists
- **500 Internal Server Error**: Something went wrong on the server

### Validation Examples

**Missing consumable for metered feature:**

```json
{
  "error": {
    "message": "Please specify whether the feature is consumable",
    "code": "validation_error",
    "path": ["consumable"]
  }
}
```

**Missing credit_schema for credit_system:**

```json
{
  "error": {
    "message": "Please specify the credit schema for the feature",
    "code": "validation_error",
    "path": ["credit_schema"]
  }
}
```

**Invalid credit_system configuration:**

```json
{
  "error": {
    "message": "Credit system features must be consumable",
    "code": "validation_error",
    "path": ["consumable"]
  }
}
```

## Feature Configuration Best Practices

### Consumable vs Allocated

Choose the right configuration for your use case:

**Consumable features** (`consumable: true`):
- API calls, tokens, messages
- Credits or points
- Processing time
- Usage accumulates over time

**Allocated features** (`consumable: false`):
- Team seats or users
- Projects or workspaces
- Concurrent connections
- Usage is a snapshot at a point in time

### Credit System Design

When creating credit systems:

1. **Start with metered features** - Create all the metered features first
2. **Define conversion rates** - Set appropriate credit costs based on resource value
3. **Test the math** - Ensure credit costs align with your pricing model

```typescript Example workflow
// 1. Create metered features
await autumn.features.create({
  id: 'api-calls',
  type: 'metered',
  consumable: true
});

await autumn.features.create({
  id: 'storage-gb',
  type: 'metered',
  consumable: true
});

// 2. Create credit system
await autumn.features.create({
  id: 'credits',
  type: 'credit_system',
  credit_schema: [
    { metered_feature_id: 'api-calls', credit_cost: 1 },
    { metered_feature_id: 'storage-gb', credit_cost: 100 }
  ]
});
```
