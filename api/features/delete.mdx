## Overview

Permanently delete a feature from your account. This action cannot be undone and will remove all feature configuration.

<Warning>
  **Deletion is permanent and irreversible.** Consider archiving the feature instead if you want to preserve historical data.
</Warning>

## Endpoint

```
DELETE /features/:feature_id
```

## Authentication

This endpoint requires authentication. Include your API key in the `Authorization` header:

```
Authorization: Bearer YOUR_API_KEY
```

## Request

### Path Parameters

<ParamField path="feature_id" type="string" required>
  The unique identifier of the feature to delete.
</ParamField>

## Response

### Success Response (200)

Returns a success confirmation.

<ResponseField name="success" type="boolean">
  Indicates whether the deletion was successful. Always `true` for successful deletions.
</ResponseField>

## Error Handling

### Common Errors

- **400 Bad Request**: Feature cannot be deleted due to dependencies
  - Feature is used in a credit system
  - Feature is attached to active products
- **401 Unauthorized**: Invalid or missing API key
- **404 Not Found**: Feature with the specified ID does not exist
- **500 Internal Server Error**: Something went wrong on the server

### Error Response Examples

**Feature used in credit system:**

```json
{
  "error": {
    "message": "Feature api-calls is used by credit system credits",
    "code": "feature_in_use"
  }
```

**Feature used in product:**

## Deletion Safety Checks

Autumn performs several safety checks before allowing a feature to be deleted:

### Credit System Dependencies

If the feature is referenced in any credit system's schema, deletion is blocked:

```typescript Example
// This feature is used in a credit system
const credits = {
  id: 'credits',
  type: 'credit_system',
  credit_schema: [
    {
      metered_feature_id: 'api-calls', // ← Cannot delete this feature
      credit_cost: 1
    }
  ]
};

// Attempting to delete will fail
try {
  await autumn.features.delete('api-calls');
} catch (error) {
  console.error('Cannot delete: Feature is used by credit system');
}
```

**Solution:** Remove the feature from the credit schema first, or delete the credit system.

### Product Entitlements

If the feature is attached to any product entitlements, deletion is blocked:

```typescript Example
// This feature is used in a product
const product = {
  id: 'pro',
  entitlements: [
    {
      feature_id: 'api-calls', // ← Cannot delete this feature
      allowance: 10000
    }
  ]
};

// Attempting to delete will fail
try {
  await autumn.features.delete('api-calls');
} catch (error) {
  console.error('Cannot delete: Feature is used in a product');
}
```

**Solution:** Remove the entitlement from the product, or archive the feature instead.

## Archive vs Delete

<Warning>
  In most cases, **archiving** is safer than deletion. Archive preserves historical data and can be reversed.
</Warning>

### When to Archive

Use archiving when:
- You want to hide the feature from the dashboard
- You need to preserve historical usage data
- The feature is attached to products or entitlements
- You might want to restore the feature later

```typescript Archive a feature
const feature = await autumn.features.update('old-feature', {
  archived: true
});

console.log('Feature archived (can be restored later)');
```

### When to Delete

Use deletion only when:
- The feature was created by mistake
- You're absolutely certain you won't need the data
- The feature has no dependencies (products, credit systems)
- You understand that deletion is permanent

```typescript Delete a feature
// Only do this if you're absolutely sure!
const result = await autumn.features.delete('test-feature');
console.log('Feature permanently deleted');
```

## Safe Deletion Workflow

Follow this workflow to safely delete a feature:

### Step 1: Check Dependencies

```typescript
// Get the feature to check its configuration
const feature = await autumn.features.retrieve('feature-to-delete');

// List all features to check for credit system references
const allFeatures = await autumn.features.list();

const creditSystems = allFeatures.list.filter(f => 
  f.type === 'credit_system' && 
  f.credit_schema?.some(item => 
    item.metered_feature_id === 'feature-to-delete'
  )
);

if (creditSystems.length > 0) {
  console.log('⚠️ Feature is used in credit systems:', creditSystems.map(c => c.id));
}
```

### Step 2: Check Product Usage

```typescript
// List products to check for entitlements
const products = await autumn.products.list();

const productsUsingFeature = products.list.filter(p =>
  p.entitlements.some(e => e.feature_id === 'feature-to-delete')
);

if (productsUsingFeature.length > 0) {
  console.log('⚠️ Feature is used in products:', productsUsingFeature.map(p => p.id));
}
```

### Step 3: Remove Dependencies

```typescript
// Remove from credit systems
for (const creditSystem of creditSystems) {
  const newSchema = creditSystem.credit_schema.filter(
    item => item.metered_feature_id !== 'feature-to-delete'
  );
  
  await autumn.features.update(creditSystem.id, {
    credit_schema: newSchema
  });
}

// Update products to remove entitlements
for (const product of productsUsingFeature) {
  // You'll need to update or remove the product
  console.log(`Update product ${product.id} to remove the feature`);
}
```

### Step 4: Delete the Feature

```typescript
// Now safe to delete
try {
  const result = await autumn.features.delete('feature-to-delete');
  console.log('✅ Feature deleted successfully');
} catch (error) {
  console.error('❌ Deletion failed:', error.message);
}
```

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="What happens to historical usage data when I delete a feature?">
    All historical usage data for the feature is permanently deleted. If you need to preserve historical data, use archiving instead.
  </Accordion>

  <Accordion title="Can I restore a deleted feature?">
    No, feature deletion is permanent and cannot be undone. You would need to recreate the feature from scratch. This is why archiving is recommended in most cases.
  </Accordion>

  <Accordion title="Will deleting a feature affect customer balances?">
    Yes, deleting a feature will remove all associated customer balances. Customers will lose access to any remaining balance for that feature.
  </Accordion>

  <Accordion title="How do I delete a feature that's used in a credit system?">
    First, update the credit system to remove the feature from its schema, then delete the feature. Alternatively, delete the entire credit system first.
  </Accordion>

  <Accordion title="Can I delete a feature that customers are actively using?">
    Technically yes, but it's not recommended. The feature must not be attached to any active products. If customers have balances, those will be lost. Consider archiving instead.
  </Accordion>

  <Accordion title="What's the difference between archiving and deleting?">
    - **Archive**: Hides the feature, preserves data, can be restored, safer
    - **Delete**: Permanently removes everything, cannot be undone, riskier
    
    Always prefer archiving unless you're absolutely certain you want permanent deletion.
  </Accordion>
</AccordionGroup>
