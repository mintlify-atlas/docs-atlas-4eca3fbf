## Overview

Update an existing feature's configuration. You can change the feature's name, type, credit schema, display settings, event names, and archive status. This endpoint allows partial updates - only include the fields you want to change.

<Warning>
  Changing a feature's type or ID can affect existing entitlements and customer balances. Use caution when modifying features that are actively in use.
</Warning>

## Endpoint

```
POST /features/:feature_id
```

## Authentication

This endpoint requires authentication. Include your API key in the `Authorization` header:

```
Authorization: Bearer YOUR_API_KEY
```

## Request

### Path Parameters

<ParamField path="feature_id" type="string" required>
  The current unique identifier of the feature to update.
</ParamField>

### Body Parameters

All parameters are optional. Only include the fields you want to update.

<ParamField body="id" type="string">
  Change the feature's unique identifier. This will update all references to the feature.
  
  <Warning>
    Changing the ID requires updating any code that references the old ID in `/track` or `/check` calls.
  </Warning>
</ParamField>

<ParamField body="name" type="string">
  Update the human-readable name of the feature.
</ParamField>

<ParamField body="type" type="enum">
  Change the feature type: `metered`, `credit_system`, or `boolean`.
  
  <Warning>
    Changing the feature type may invalidate existing configuration and affect customer balances.
  </Warning>
</ParamField>

<ParamField body="consumable" type="boolean">
  **Required when changing type to metered.** Specifies whether the feature is consumable or allocated:
  
  - `true` - Consumable (usage accumulates)
  - `false` - Allocated (usage is a snapshot)
</ParamField>

<ParamField body="credit_schema" type="array">
  Update the credit conversion schema. Only applicable for credit_system features.
  
  <Expandable title="Credit Schema Item">
    <ParamField body="metered_feature_id" type="string" required>
      ID of the metered feature.
    </ParamField>
    
    <ParamField body="credit_cost" type="number" required>
      Number of credits required per unit.
    </ParamField>
  </Expandable>
  
  Set to `null` to remove the credit schema.
</ParamField>

<ParamField body="display" type="object">
  Update display names for proper pluralization.
  
  <Expandable title="properties">
    <ParamField body="singular" type="string">
      Singular form.
    </ParamField>
    
    <ParamField body="plural" type="string">
      Plural form.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="event_names" type="array">
  Update the array of event names that trigger usage tracking.
</ParamField>

<ParamField body="archived" type="boolean">
  Archive or unarchive the feature:
  
  - `true` - Archive the feature (hides from dashboard and list endpoint)
  - `false` - Unarchive the feature
  
  Archived features preserve historical data but stop accepting new usage events.
</ParamField>

## Response

### Success Response (200)

Returns the updated feature object.

<ResponseField name="id" type="string">
  The unique identifier for the feature (updated if changed).
</ResponseField>

<ResponseField name="name" type="string">
  The human-readable name of the feature.
</ResponseField>

<ResponseField name="type" type="enum">
  The feature type: `metered`, `credit_system`, or `boolean`.
</ResponseField>

<ResponseField name="consumable" type="boolean">
  Whether the feature is consumable. Only present for metered features.
</ResponseField>

<ResponseField name="credit_schema" type="array">
  Credit conversion schema. Only present for credit_system features.
</ResponseField>

<ResponseField name="display" type="object">
  Display names for the feature.
</ResponseField>

<ResponseField name="event_names" type="array">
  Array of event names that trigger usage tracking.
</ResponseField>

<ResponseField name="archived" type="boolean">
  Whether the feature is archived.
</ResponseField>

## Examples

### Update Display Names

<CodeGroup>

```bash cURL
curl -X POST https://api.autumnhq.com/v1/features/api-calls \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "display": {
      "singular": "API Request",
      "plural": "API Requests"
    }
  }'
```

```typescript TypeScript
import { AutumnClient } from '@useautumn/autumn-js';

const autumn = new AutumnClient({
  apiKey: 'YOUR_API_KEY'
});

const feature = await autumn.features.update('api-calls', {
  display: {
    singular: 'API Request',
    plural: 'API Requests'
  }
});

console.log(`Updated display: ${feature.display.plural}`);
```

```python Python
from autumn import AutumnClient

autumn = AutumnClient(api_key='YOUR_API_KEY')

feature = autumn.features.update(
    'api-calls',
    display={
        'singular': 'API Request',
        'plural': 'API Requests'
    }
)

print(f"Updated display: {feature['display']['plural']}")
```

</CodeGroup>

### Response

```json
{
  "id": "api-calls",
  "name": "API Calls",
  "type": "metered",
  "consumable": true,
  "display": {
    "singular": "API Request",
    "plural": "API Requests"
  },
  "event_names": ["api_call"],
  "archived": false
}
```

## Error Handling

### Common Errors

- **400 Bad Request**: Invalid request parameters
  - Missing `consumable` when changing type to metered
  - Invalid field values
- **401 Unauthorized**: Invalid or missing API key
- **404 Not Found**: Feature with the specified ID does not exist
- **409 Conflict**: New ID already exists as another feature
- **500 Internal Server Error**: Something went wrong on the server

### Error Response Examples

**Missing consumable when changing type:**

```json
{
  "error": {
    "message": "Consumable is required when changing type to metered",
    "code": "validation_error"
  }
}
```

**Feature not found:**

```json
{
  "error": {
    "message": "Feature with id unknown-feature not found",
    "code": "feature_not_found"
  }
}
```

## Update Safety Guidelines

### Safe Updates

These changes are safe and won't affect existing functionality:

- **Display names** - UI only, no functional impact
- **Feature name** - Descriptive text only
- **Event names** - Affects future events only
- **Archive status** - Reversible, preserves data

### Caution Required

These changes can affect existing functionality:

- **Feature ID** - Requires updating all code references
- **Feature type** - May invalidate configuration and affect balances
- **Credit schema** - Changes conversion rates for future usage
- **Consumable flag** - Changes how usage is tracked

### Best Practices

<Warning>
  Always test updates in development environment before applying to production.
</Warning>

**When changing IDs:**
1. Update all code that references the old ID
2. Update any documentation or configuration
3. Notify your team of the change

**When modifying credit schemas:**
1. Understand the impact on customer balances
2. Consider creating a new feature version instead
3. Communicate rate changes to customers

**When archiving features:**
1. Ensure no active products depend on the feature
2. Consider the impact on customer access
3. Use archive instead of delete to preserve history
