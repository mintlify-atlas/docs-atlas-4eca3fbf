---
title: 'Update Feature'
description: 'Update an existing feature'
api: 'POST /v1/features/{feature_id}'
---

Updates an existing feature. You can modify the feature's properties, including its name, type, and configuration.

## Path Parameters

<ParamField path="feature_id" type="string" required>
  The unique identifier of the feature to update.
  
  Example: `api_calls`
</ParamField>

## Request Body

All fields are optional. Only include the fields you want to update.

<ParamField body="id" type="string">
  The new unique identifier for the feature. Use this to rename the feature's ID.
  
  **Note:** Changing the ID will require updating all references to this feature in your codebase.
</ParamField>

<ParamField body="name" type="string">
  The new human-readable name of the feature.
</ParamField>

<ParamField body="type" type="enum">
  The new type of the feature:
  - `boolean` - Simple on/off feature flag
  - `metered` - Usage-based feature with consumption tracking
  - `credit_system` - Credit-based feature that unifies multiple metered features
  
  **Note:** When changing the type to `metered`, you must also provide the `consumable` field.
</ParamField>

<ParamField body="consumable" type="boolean">
  Whether the feature is consumable.
  
  - `true` - Consumable features are depleted with usage (e.g., API calls, tokens)
  - `false` - Non-consumable features are allocated (e.g., seats, workspaces)
  
  **Required when changing `type` to `metered`.**
</ParamField>

<ParamField body="display" type="object">
  Display names for the feature in your user interface.
  
  <Expandable title="Display Object">
    <ParamField body="singular" type="string">
      Singular form of the feature name.
    </ParamField>
    
    <ParamField body="plural" type="string">
      Plural form of the feature name.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="event_names" type="array">
  Array of event names that trigger usage tracking for this feature.
</ParamField>

<ParamField body="credit_schema" type="array">
  Credit conversion schema for `credit_system` type features.
  
  <Expandable title="Credit Schema Item">
    <ParamField body="metered_feature_id" type="string" required>
      The ID of the metered feature that consumes credits.
    </ParamField>
    
    <ParamField body="credit_cost" type="number" required>
      The number of credits consumed per unit of the metered feature.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="archived" type="boolean">
  Whether to archive the feature. Archived features are hidden from the dashboard and list endpoints but remain accessible via direct API calls.
  
  Set to `true` to archive, `false` to unarchive.
</ParamField>

## Response

Returns the updated feature object.

<ResponseField name="id" type="string" required>
  The unique identifier for the feature.
</ResponseField>

<ResponseField name="name" type="string" required>
  The human-readable name of the feature.
</ResponseField>

<ResponseField name="type" type="enum" required>
  The type of the feature.
</ResponseField>

<ResponseField name="consumable" type="boolean" required>
  Whether the feature is consumable.
</ResponseField>

<ResponseField name="display" type="object">
  Display names for the feature.
</ResponseField>

<ResponseField name="event_names" type="array">
  Array of event names that trigger usage tracking.
</ResponseField>

<ResponseField name="credit_schema" type="array">
  Credit conversion schema (only for credit_system features).
</ResponseField>

<ResponseField name="archived" type="boolean" required>
  Whether the feature is archived.
</ResponseField>

## Error Codes

| Status Code | Error Code | Description |
|------------|------------|-------------|
| 400 | `validation_error` | Invalid field values or missing required fields |
| 401 | `unauthorized` | Invalid or missing API key |
| 403 | `forbidden` | Insufficient permissions |
| 404 | `feature_not_found` | The feature does not exist |
| 409 | `already_exists` | The new ID already exists |
| 500 | `internal_error` | An unexpected error occurred |

## Important Notes

- When changing `type` to `metered`, you must provide the `consumable` field
- Archiving a feature does not delete it - it only hides it from list endpoints and the dashboard
- Updating a feature's ID will require updating all references in your codebase
- You cannot modify features that are actively used in products without first removing them from those products
