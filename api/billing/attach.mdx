## Overview

The attach endpoint enables a product for a customer with fine-grained control over billing behavior, prorations, and payment collection. Use this endpoint when you need precise control over how charges are applied and when products are activated.

For simpler use cases, see the legacy [/attach](/api/attach) endpoint.

## Authentication

This endpoint requires API key authentication. Include your API key in the request header:

```bash
Authorization: Bearer YOUR_API_KEY
```

## Example Request

<CodeGroup>
```bash cURL
curl -X POST https://api.useautumn.com/billing/attach \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "customer_id": "cus_123",
    "product_id": "pro_plan",
    "billing_behavior": "prorate_immediately",
    "options": [
      {
        "feature_id": "seats",
        "quantity": 5
      }
    ]
  }'
```

```typescript TypeScript
import { Autumn } from '@useautumn/sdk';

const autumn = new Autumn({ apiKey: 'YOUR_API_KEY' });

const result = await autumn.billing.attach({
  customer_id: 'cus_123',
  product_id: 'pro_plan',
  billing_behavior: 'prorate_immediately',
  options: [
    {
      feature_id: 'seats',
      quantity: 5
    }
  ]
});

if (result.payment_url) {
  console.log('Payment required:', result.payment_url);
} else {
  console.log('Product attached successfully');
}
```

```python Python
from autumn import Autumn

autumn = Autumn(api_key='YOUR_API_KEY')

result = autumn.billing.attach(
  customer_id='cus_123',
  product_id='pro_plan',
  billing_behavior='prorate_immediately',
  options=[
    {
      'feature_id': 'seats',
      'quantity': 5
    }
  ]
)

if result.get('payment_url'):
    print(f"Payment required: {result['payment_url']}")
else:
    print('Product attached successfully')
```
</CodeGroup>

## Billing Behavior

The `billing_behavior` parameter controls how charges are applied when attaching a product:

### prorate_immediately (default)

Charges are calculated and applied immediately, with prorations for mid-cycle changes:

```json
{
  "billing_behavior": "prorate_immediately"
}
```

**Use when:**
- Customer is upgrading/downgrading mid-cycle
- You want immediate payment collection
- Prorated charges should appear on current invoice

### next_cycle_only

No charges are created immediately. The product becomes active, but payment is deferred to the next billing cycle:

```json
{
  "billing_behavior": "next_cycle_only"
}
```

**Use when:**
- Customer should have access immediately without payment
- You want to batch changes into next invoice
- Avoiding mid-cycle proration complexity

## Error Responses

<ResponseField name="error" type="object">
  <Expandable title="Error Object">
    <ResponseField name="code" type="string">
      Error code identifying the type of error.
      
      Common error codes:
      - `customer_not_found` - The specified customer does not exist
      - `product_not_found` - The specified product does not exist
      - `payment_method_required` - Customer has no payment method on file
      - `already_subscribed` - Customer already has this product
      - `invalid_billing_behavior` - Invalid billing_behavior value
      - `stripe_error` - Error from Stripe API
    </ResponseField>
    <ResponseField name="message" type="string">
      Human-readable error message.
    </ResponseField>
  </Expandable>
</ResponseField>
