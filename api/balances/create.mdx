---
title: "Create Balance"
api: "POST /balances/create"
description: "Create a new balance for a specific feature for a customer"
---

Create a new balance (customer entitlement) for a specific feature. This allows you to grant feature access or usage limits to customers independently of product subscriptions.

## Request

<ParamField body="feature_id" type="string" required>
  The feature ID to create the balance for. The feature must exist in your organization.
</ParamField>

<ParamField body="customer_id" type="string" required>
  The customer ID to assign the balance to. The customer must exist in your organization.
</ParamField>

<ParamField body="entity_id" type="string">
  Entity ID for entity-scoped balances. Use this when you want to track balances at the entity level rather than the customer level.
</ParamField>

<ParamField body="included" type="number">
  The initial balance amount to grant. For metered features, this represents the usage limit. Cannot be used with `unlimited`.
</ParamField>

<ParamField body="granted_balance" type="number">
  Alternative to `included`. The balance amount to grant to the customer.
</ParamField>

<ParamField body="unlimited" type="boolean">
  Whether the balance is unlimited. When true, the customer has unlimited access to the feature. Cannot be used with `included` or `reset`.
</ParamField>

<ParamField body="reset" type="object">
  Reset configuration for the balance. Defines when and how the balance should automatically reset.

  <Expandable title="Reset Object">
    <ParamField body="interval" type="string" required>
      The reset interval. One of: `daily`, `weekly`, `monthly`, `yearly`.
    </ParamField>

    <ParamField body="interval_count" type="number">
      The number of intervals between resets. For example, `interval_count: 2` with `interval: monthly` resets every 2 months.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="expires_at" type="number">
  Unix timestamp (milliseconds) when the balance expires. After this time, the balance will no longer be valid.
</ParamField>

## Response

<ResponseField name="success" type="boolean">
  Returns `true` if the balance was created successfully.
</ResponseField>

## Code Examples

<CodeGroup>
```typescript TypeScript
const response = await fetch('https://api.autumn.com/v1/balances/create', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer YOUR_API_KEY',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    feature_id: 'credits',
    customer_id: 'cus_123',
    included: 1000,
    reset: {
      interval: 'monthly',
      interval_count: 1
    }
  })
});

const data = await response.json();
console.log(data.success); // true
```

```python Python
import requests

response = requests.post(
    'https://api.autumn.com/v1/balances/create',
    headers={

        'Content-Type': 'application/json'
    },
    json={
        'feature_id': 'credits',
        'customer_id': 'cus_123',
        'included': 1000,
        'reset': {
            'interval': 'monthly',
            'interval_count': 1
        }
    }
)

data = response.json()
print(data['success'])  # True
```

## Error Handling

<ResponseField name="400" type="error">
  **Bad Request** - Invalid parameters. Common causes:
  - Missing required fields (feature_id, customer_id)
  - Both `included` and `unlimited` specified
  - `unlimited` specified with `reset`
  - Invalid feature type (e.g., boolean feature with balance)
</ResponseField>

<ResponseField name="401" type="error">
  **Unauthorized** - Invalid or missing API key.
</ResponseField>

<ResponseField name="404" type="error">
  **Not Found** - The specified feature or customer does not exist.
</ResponseField>

<ResponseField name="500" type="error">
  **Internal Server Error** - An unexpected error occurred on the server.
</ResponseField>
