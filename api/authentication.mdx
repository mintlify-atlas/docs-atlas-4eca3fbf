## API Keys

The Autumn API uses API keys to authenticate requests. You can create and manage your API keys from the Autumn dashboard.

### Key Types

Autumn provides two types of API keys:

**Secret Keys** (Server-side)
- Used for server-to-server API calls
- Have full access to all API endpoints
- Must be kept secure and never exposed in client-side code
- Format: `am_test_xxx` or `am_live_xxx`

**Publishable Keys** (Client-side)
- Used for client-side integrations
- Have limited access to public endpoints only
- Safe to expose in frontend code
- Format: `am_pk_test_xxx` or `am_pk_live_xxx`

### Environment Prefixes

API keys are prefixed to indicate their environment:

- `am_test_` - Test mode secret key
- `am_live_` - Live mode secret key  
- `am_pk_test_` - Test mode publishable key
- `am_pk_live_` - Live mode publishable key

## Making Authenticated Requests

Include your API key in the `Authorization` header using the Bearer authentication scheme:

```bash
curl https://api.useautumn.com/v1/customers \
  -H "Authorization: Bearer am_live_sk_xxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json"
```

### Example with Secret Key

<CodeGroup>

```bash cURL
curl https://api.useautumn.com/v1/customers/cus_123 \
  -H "Authorization: Bearer am_live_sk_xxxxxxxxxxxxxxxx"
```

```javascript Node.js
const response = await fetch('https://api.useautumn.com/v1/customers/cus_123', {
  headers: {
    'Authorization': 'Bearer am_live_sk_xxxxxxxxxxxxxxxx',
    'Content-Type': 'application/json'
  }
});
```

```python Python
import requests

response = requests.get(
    'https://api.useautumn.com/v1/customers/cus_123',
    headers={
        'Authorization': 'Bearer am_live_sk_xxxxxxxxxxxxxxxx'
    }
)
```

</CodeGroup>

## Authentication Errors

If authentication fails, the API returns a `401 Unauthorized` status code:

### Missing API Key

```json
{
  "message": "Secret key not found in Authorization header",
  "code": "no_secret_key"
}
```

### Invalid API Key

```json
{
  "message": "Invalid secret key: am_live_sk_xxx***",
  "code": "invalid_secret_key"
}
```

The API key is partially masked in error messages for security.

### Invalid Format

If the key doesn't start with `am_`:

```json
{
  "message": "Invalid secret key",
  "code": "invalid_secret_key"
}
```

## Publishable Keys

Publishable keys can only be used with specific public endpoints:

- `/v1/check` - Check feature access
- `/v1/entitled` - Verify entitlements

Attempting to use a publishable key on other endpoints returns:

```json
{
  "message": "This endpoint is not accessible with a publishable key",
  "code": "endpoint_not_public"
}
```

## Dashboard Authentication

Requests from the Autumn dashboard are authenticated using Better Auth session cookies. If you're building a custom dashboard, you can use the dashboard authentication flow by setting:

```
x-client-type: dashboard
```

This is handled automatically by the official Autumn SDKs.

## Best Practices

<AccordionGroup>
  <Accordion title="Keep secret keys secure">
    - Never commit API keys to version control
    - Use environment variables to store keys
    - Rotate keys regularly
    - Use test keys for development
  </Accordion>
  
  <Accordion title="Use the right key type">
    - Use secret keys for server-side operations
    - Use publishable keys for client-side integrations
    - Never expose secret keys in frontend code
  </Accordion>
  
  <Accordion title="Separate test and live environments">
    - Use test keys during development
    - Switch to live keys only in production
    - Test mode and live mode data is completely isolated
  </Accordion>
</AccordionGroup>

## Creating API Keys

1. Log in to the [Autumn Dashboard](https://app.useautumn.com)
2. Navigate to **Settings** → **API Keys**
3. Click **Create API Key**
4. Choose the environment (Test or Live)
5. Copy and securely store your key

<Warning>
  API keys are only shown once during creation. If you lose a key, you'll need to create a new one.
</Warning>

## Key Management

### Rotating Keys

To rotate an API key:

1. Create a new API key
2. Update your application to use the new key
3. Test that the new key works
4. Delete the old key from the dashboard

### Revoking Keys

If a key is compromised:

1. Immediately revoke it from the dashboard
2. Create a new key
3. Update all applications using the old key

Revoked keys return an `invalid_secret_key` error.
