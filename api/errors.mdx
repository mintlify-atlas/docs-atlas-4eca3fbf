## Error Response Format

When an error occurs, the API returns a JSON response with an appropriate HTTP status code:

```json
{
  "message": "Customer not found",
  "code": "customer_not_found",
  "env": "test"
}
```

All error responses include:

- `message` - Human-readable error description
- `code` - Machine-readable error code for programmatic handling
- `env` - The environment where the error occurred (`test` or `live`)

## HTTP Status Codes

The API uses standard HTTP status codes:

| Status Code | Meaning |
|-------------|----------|
| `200` | OK - Request succeeded |
| `400` | Bad Request - Invalid request parameters |
| `401` | Unauthorized - Authentication failed |
| `404` | Not Found - Resource doesn't exist |
| `429` | Too Many Requests - Rate limit exceeded |
| `500` | Internal Server Error - Something went wrong |

## Error Types

### Authentication Errors (401)

<AccordionGroup>
  <Accordion title="no_secret_key">
    Missing Authorization header.
    
    ```json
    {
      "message": "Secret key not found in Authorization header",
      "code": "no_secret_key"
    }
    ```
    
    **Solution:** Include `Authorization: Bearer YOUR_API_KEY` header.
  </Accordion>
  
  <Accordion title="invalid_secret_key">
    Invalid or revoked API key.
    
    ```json
    {
      "message": "Invalid secret key: am_live_sk_xxx***",
      "code": "invalid_secret_key"
    }
    ```
    
    **Solution:** Verify your API key is correct and not revoked.
  </Accordion>
  
  <Accordion title="invalid_publishable_key">
    Invalid publishable key.
    
    ```json
    {
      "message": "Invalid publishable key",
      "code": "invalid_publishable_key"
    }
    ```
    
    **Solution:** Check your publishable key is valid.
  </Accordion>
  
  <Accordion title="endpoint_not_public">
    Attempted to use publishable key on a secret-only endpoint.
    
    ```json
    {
      "message": "This endpoint is not accessible with a publishable key",
      "code": "endpoint_not_public"
    }
    ```
    
    **Solution:** Use a secret key for this endpoint.
  </Accordion>
</AccordionGroup>

    Malformed or conflicting request.

  <Accordion title="invalid_options">
    Invalid configuration or options.
    
    ```json
    {
      "message": "Invalid pricing configuration",
      "code": "invalid_options"
    }
    ```
    
    **Solution:** Verify your configuration matches requirements.
  </Accordion>
  
  <Accordion title="invalid_api_version">


## Error Handling Best Practices

### Check the Status Code

```javascript
const response = await fetch('https://api.useautumn.com/v1/customers', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${apiKey}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({ customer_id: 'cus_123' })
});

if (!response.ok) {
  const error = await response.json();
  console.error(`Error ${response.status}: ${error.code} - ${error.message}`);
}
```

### Handle Specific Error Codes

```javascript
try {
  const customer = await autumnClient.customers.create({ 
    customer_id: 'cus_123' 
  });
} catch (error) {
  switch (error.code) {
    case 'duplicate_customer_id':
      // Customer already exists, fetch instead
      return await autumnClient.customers.retrieve('cus_123');
    
    case 'invalid_inputs':
      // Validation error, log and notify user
      console.error('Invalid customer data:', error.message);
      break;
    
    case 'stripe_card_declined':
      // Payment failed, prompt for new payment method
      showPaymentError('Card declined');
      break;
    
    default:
      // Unexpected error
      throw error;
  }
}
```

### Implement Retry Logic

For `500` errors and rate limits, implement exponential backoff:

```javascript
async function fetchWithRetry(url, options, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    const response = await fetch(url, options);
    
    if (response.ok) {
      return response;
    }
    
    // Retry on 500 errors and rate limits
    if (response.status >= 500 || response.status === 429) {
      const delay = Math.pow(2, i) * 1000; // Exponential backoff
      await new Promise(resolve => setTimeout(resolve, delay));
      continue;
    }
    
    // Don't retry client errors
    throw new Error(`HTTP ${response.status}`);
  }
}
```

### Log Errors for Debugging

Always log error details for troubleshooting:

```javascript
catch (error) {
  console.error('Autumn API Error:', {
    code: error.code,
    message: error.message,
    env: error.env,
    timestamp: new Date().toISOString()
  });
}
```
