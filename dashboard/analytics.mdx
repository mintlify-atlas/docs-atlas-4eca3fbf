The Analytics section helps you understand how customers are using your product by tracking events and visualizing usage patterns over time.

## Events Overview

Events represent actions tracked in your application through the `track` API:

```typescript
// Track a usage event
await autumn.track({
  customerId: "cus_123",
  featureKey: "api-calls",
  usage: 1,
  properties: {
    endpoint: "/api/users",
    method: "GET",
    responseTime: 245
  }
});
```

Each event contains:
- **Event name** - Feature key or custom event identifier
- **Customer ID** - Who performed the action
- **Timestamp** - When the event occurred
- **Usage** - Quantity consumed (for metered features)
- **Properties** - Custom metadata about the event

## Event Properties

Enhance events with custom properties for deeper insights:

### Standard Properties

Common properties for all events:

- **customer_id** - Who triggered the event (required)
- **feature_key** - What was used (required for metered features)
- **usage** - Quantity consumed (defaults to 1)
- **timestamp** - When it occurred (defaults to now)
- **entity_id** - Which workspace/project (for multi-tenant apps)

### Custom Properties

Add any JSON-serializable data:

```typescript
// Track an API call with detailed properties
await autumn.track({
  customerId: "cus_123",
  featureKey: "api-calls",
  usage: 1,
  properties: {
    // Request details
    endpoint: "/api/users",
    method: "GET",
    
    // Performance metrics
    responseTime: 245,
    cacheHit: true,
    
    // User context
    userId: "usr_456",
    ipAddress: "192.168.1.1",
    
    // Business data
    plan: "pro",
    billingRegion: "us-east"
  }
});
```

**Best practices for properties:**
- Use consistent naming conventions (camelCase or snake_case)
- Keep property names descriptive but concise
- Avoid deeply nested objects
- Don't include sensitive data (passwords, tokens, etc.)
- Use numbers for metrics that you may want to aggregate

<Warning>
  Event properties are stored as-is and cannot be modified after the event is created. Ensure you're not logging sensitive information.
</Warning>

## Use Cases

### Monitor API Usage

Track API calls and identify heavy users:

```typescript
// Track every API request
await autumn.track({
  customerId: req.customerId,
  featureKey: "api-calls",
  usage: 1,
  properties: {
    endpoint: req.path,
    method: req.method,
    statusCode: res.statusCode,
    responseTime: res.duration
  }
});
```

**Dashboard benefits:**
- See which endpoints are most popular
- Identify customers approaching limits
- Detect unusual usage patterns
- Optimize infrastructure based on trends

### Track Feature Adoption

Measure how customers use different features:

```typescript
// Track feature usage
await autumn.track({
  customerId: user.id,
  featureKey: "exports",
  usage: 1,
  properties: {
    format: "csv",
    rowCount: 1500,
    fileSize: 245000
  }
});
```

**Dashboard benefits:**
- See which features are most valuable
- Identify underutilized features
- Validate product roadmap decisions
- Calculate feature ROI

### Analyze User Behavior

Understand customer workflows:

```typescript
// Track user actions
await autumn.track({
  customerId: user.id,
  featureKey: "document-created",
  usage: 1,
  properties: {
    template: "invoice",
    collaborators: 3,
    automationEnabled: true
  }
});
```

**Dashboard benefits:**
- Identify power users
- Understand common workflows
- Detect friction points
- Personalize onboarding

## Performance Considerations

### Retention Periods

Event data is retained based on your plan:

- **Sandbox** - 30 days
- **Starter** - 90 days
- **Pro** - 1 year
- **Enterprise** - Custom retention

<Tip>
  Export historical data regularly if you need longer retention than your plan provides.
</Tip>

### Query Optimization

For best performance:

- Use shorter time ranges when possible
- Limit custom properties to essential data
- Avoid deeply nested property objects
- Batch track calls when tracking multiple events

## Best Practices

### Event Naming

- Use descriptive, action-based names: `api-call`, `export-created`, `user-login`
- Use kebab-case for consistency
- Match feature keys for metered features
- Avoid generic names like `event` or `action`

### Property Design

- Include context that helps explain the event
- Use consistent types (always string, always number, etc.)
- Flatten nested objects when possible
- Document property meanings for your team

### Monitoring Strategy

- Check analytics daily for unusual patterns
- Set up alerts for usage anomalies (via webhooks)
- Review customer usage before renewal dates
- Use trends to inform product decisions
