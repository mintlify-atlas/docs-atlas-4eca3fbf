The Analytics section helps you understand how customers are using your product by tracking events and visualizing usage patterns over time.

## Events Overview

Events represent actions tracked in your application through the `track` API:

```typescript
// Track a usage event
await autumn.track({
  customerId: "cus_123",
  featureKey: "api-calls",
  usage: 1,
  properties: {
    endpoint: "/api/users",
    method: "GET",
    responseTime: 245
  }
});
```

Each event contains:
- **Event name** - Feature key or custom event identifier
- **Customer ID** - Who performed the action
- **Timestamp** - When the event occurred
- **Usage** - Quantity consumed (for metered features)
- **Properties** - Custom metadata about the event
- **Entity ID** - Associated workspace/project (optional)

## Events Page

Access the Events page from the main sidebar to view organization-wide event data:

### Page Layout

The Events page is divided into two main sections:

**Usage Chart (top)**
- Visual timeseries of event volume
- 400px fixed height for consistent viewing
- Interactive tooltips and filtering

**Event Table (bottom)**
- Detailed event log with all properties
- Flexible height that grows with content
- Pagination controls for large datasets

### Query Topbar

Powerful filtering controls above the chart:

**Time range selector:**
- Last 7 days
- Last 30 days  
- Last 90 days
- Custom date range

**Bin size selector:**
- **Day** - Daily aggregation (default)
- **Week** - Weekly rollups
- **Month** - Monthly summaries

**Event filter:**
- Select specific events to display
- Multi-select dropdown
- Filter by feature key
- Show all or specific events

**Feature filter:**
- Filter by feature ID
- View usage for specific features
- Combine with event filters

**Group by dropdown:**
- Group events by property
- Split chart into multiple series
- Available properties auto-detected
- Includes `customer_id` and custom properties

<Tip>
  Use shorter time ranges (7 days) for real-time monitoring and longer ranges (30 days) for trend analysis.
</Tip>

### Usage Chart

Interactive bar chart showing event volume over time:

**Chart features:**
- Color-coded bars for each event type
- Stacked bars when multiple events selected
- Hover tooltips with exact counts
- Responsive design adapts to screen size
- Smooth animations on data updates

**Multiple series:**
When grouping by property:
- Each unique value gets its own color
- Legend shows all groups
- Click legend items to toggle visibility
- Top 10 groups by volume (if >10 exist)

**Empty states:**
- "No events found" when filters return nothing
- Helpful message suggests widening filters
- Prompt to select events if none chosen

<Warning>
  When grouped data has too many unique values (>10), only the top groups by volume are shown. A toast notification alerts you to this truncation.
</Warning>

### Event Table

Detailed, paginated log of all events:

**Base columns:**
- **Event name** - Feature key or event type
- **Timestamp** - When event occurred (with timezone)
- **Customer ID** - Who triggered the event
- **Usage** - Quantity tracked (for metered events)

**Dynamic property columns:**
The table automatically generates columns from event properties:
- Common properties (appearing in multiple events) become columns
- `properties.endpoint` → "Endpoint" column
- `properties.method` → "Method" column  
- Custom properties from your events
- Nested properties flattened (e.g., `properties.user.id`)

**Column visibility:**
Hide or show columns as needed:
- Click column visibility button
- Toggle individual columns
- Changes persist across sessions

**Pagination controls:**
- Page size selector (500, 1000, 2000)
- Next/previous page buttons
- Current page indicator
- Total event count

<Note>
  The event table uses AG Grid for high performance. It can handle thousands of events with smooth scrolling and sorting.
</Note>

### Group By Analysis

Powerful feature to segment event data:

**How it works:**
1. Select property from **Group by** dropdown
2. Chart splits into series per unique value
3. Each series gets a distinct color
4. Table shows property as a column
5. Filter to specific group value

**Example: Group by endpoint**
```
Chart shows:
- Blue bars: /api/users
- Green bars: /api/posts  
- Red bars: /api/comments

Table adds "Endpoint" column showing value per event
```

**Group filter:**
After grouping, filter to specific value:
- Dropdown appears with available groups
- Select one to show only that group's data
- Chart and table both filter
- Clear to show all groups again

**Available properties:**
- `customer_id` (always available)
- Any property sent in event `properties`
- Extracted from recent events
- Updates as new events arrive

<Tip>
  Group by endpoint to see which APIs are most used. Group by customer_id to compare customer activity. Group by custom properties for business-specific insights.
</Tip>

### Truncation Handling

When grouped data has >10 unique values:

- Only top 10 by volume are shown
- Toast notification informs you
- Use group filter to see specific values
- Or adjust date range to reduce cardinality

## Event Properties

Enhance events with custom properties for deeper insights:

### Standard Properties

Common properties for all events:

- **customer_id** - Who triggered the event (required)
- **feature_key** - What was used (required for metered features)
- **usage** - Quantity consumed (defaults to 1)
- **timestamp** - When it occurred (defaults to now)
- **entity_id** - Which workspace/project (for multi-tenant apps)
- **idempotency_key** - Prevent duplicate events

### Custom Properties

Add any JSON-serializable data:

```typescript
// Track an API call with detailed properties
await autumn.track({
  customerId: "cus_123",
  featureKey: "api-calls",
  usage: 1,
  properties: {
    // Request details
    endpoint: "/api/users",
    method: "GET",
    
    // Performance metrics
    responseTime: 245,
    cacheHit: true,
    
    // User context
    userId: "usr_456",
    ipAddress: "192.168.1.1",
    
    // Business data
    plan: "pro",
    billingRegion: "us-east"
  }
});
```

**Property types:**
- **Strings** - Text values, IDs, names
- **Numbers** - Metrics, counts, durations
- **Booleans** - Flags, toggles
- **Dates** - ISO 8601 strings
- **Arrays** - Lists of values (flattened in table)
- **Objects** - Nested data (flattened with dot notation)

**Best practices for properties:**
- Use consistent naming conventions (camelCase or snake_case)
- Keep property names descriptive but concise
- Avoid deeply nested objects (2-3 levels max)
- Don't include sensitive data (passwords, tokens, PII)
- Use numbers for metrics that you may want to aggregate
- Standardize property names across events

<Warning>
  Event properties are stored as-is and cannot be modified after the event is created. Ensure you're not logging sensitive information.
</Warning>

## Performance and Storage

### ClickHouse Integration

Autumn uses ClickHouse for fast event analytics:

**Benefits:**
- Sub-second queries on millions of events
- Real-time aggregations
- Efficient columnar storage
- Automatic data compression

**Pre-aggregated data:**
For timeseries charts:
- Daily rollups computed automatically
- Feature breakdowns pre-calculated
- Faster chart rendering
- Reduced query load

**Raw events:**
For detailed analysis:
- Individual event records
- Full property access
- Exact timestamps
- Complete audit trail

<Note>
  If ClickHouse is not enabled for your organization, the Analytics page will display a message. Contact support to enable event analytics.
</Note>

### Retention Periods

Event data is retained based on your plan:

- **Sandbox** - 30 days of events
- **Starter** - 90 days of events
- **Pro** - 1 year of events
- **Enterprise** - Custom retention (up to 5 years)

<Tip>
  Export historical data regularly if you need longer retention than your plan provides.
</Tip>

### Query Optimization

For best performance:

- Use shorter time ranges when possible (7-30 days)
- Limit custom properties to essential data
- Avoid deeply nested property objects
- Use consistent property types
- Batch track calls when tracking multiple events
- Set appropriate bin sizes (day for <30 days, week for >30 days)

## Use Cases

### Monitor API Usage

Track API calls and identify heavy users:

```typescript
// Track every API request
await autumn.track({
  customerId: req.customerId,
  featureKey: "api-calls",
  usage: 1,
  properties: {
    endpoint: req.path,
    method: req.method,
    statusCode: res.statusCode,
    responseTime: res.duration
  }
});
```

**Dashboard benefits:**
- See which endpoints are most popular (group by endpoint)
- Identify customers approaching limits
- Detect unusual usage patterns (spikes, drops)
- Optimize infrastructure based on trends
- Track error rates by status code

### Track Feature Adoption

Measure how customers use different features:

```typescript
// Track feature usage
await autumn.track({
  customerId: user.id,
  featureKey: "exports",
  usage: 1,
  properties: {
    format: "csv",
    rowCount: 1500,
    fileSize: 245000
  }
});
```

**Dashboard benefits:**
- See which features are most valuable
- Identify underutilized features
- Validate product roadmap decisions
- Calculate feature ROI
- Compare adoption across customer segments

### Analyze User Behavior

Understand customer workflows:

```typescript
// Track user actions
await autumn.track({
  customerId: user.id,
  featureKey: "document-created",
  usage: 1,
  properties: {
    template: "invoice",
    collaborators: 3,
    automationEnabled: true
  }
});
```

**Dashboard benefits:**
- Identify power users
- Understand common workflows
- Detect friction points
- Personalize onboarding
- Predict churn risk

### Performance Monitoring

Track application performance:

```typescript
await autumn.track({
  customerId: user.id,
  featureKey: "page-view",
  usage: 1,
  properties: {
    page: "/dashboard",
    loadTime: 1250,
    browserCached: true
  }
});
```

**Dashboard benefits:**
- Monitor response times (average responseTime property)
- Identify slow endpoints
- Track cache hit rates
- Detect performance regressions

## Best Practices

### Event Naming

- Use descriptive, action-based names: `api-call`, `export-created`, `user-login`
- Use kebab-case for consistency
- Match feature keys for metered features
- Avoid generic names like `event` or `action`
- Be specific: `document-created` not `create`

### Property Design

- Include context that helps explain the event
- Use consistent types (always string, always number, etc.)
- Flatten nested objects when possible
- Document property meanings for your team
- Create a property schema or dictionary
- Use enums for categorical data

### Monitoring Strategy

- Check analytics daily for unusual patterns
- Set up alerts for usage anomalies (via webhooks)
- Review customer usage before renewal dates
- Use trends to inform product decisions
- Compare week-over-week growth
- Track feature adoption rates

### Dashboard Usage

- Save common filter combinations
- Use grouping to segment data
- Export data for deeper analysis
- Share insights with your team
- Set up regular reporting cadences
