## Overview

**Products** (also called **Plans**) are the core building blocks of your pricing model in Autumn. They define:

- What customers can subscribe to
- How much it costs
- What features and limits are included
- Billing frequency and intervals
- Free trial configurations

Products bundle together features, pricing, and entitlements into a cohesive offering that customers can purchase.

## Product Structure

Every product contains these core elements:

<ParamField path="id" type="string" required>
  Unique identifier for the product (e.g., `starter`, `pro`, `enterprise`)
</ParamField>

<ParamField path="name" type="string" required>
  Human-readable name displayed to customers
</ParamField>

<ParamField path="description" type="string">
  Optional description of what the product offers
</ParamField>

<ParamField path="price" type="object">
  Base subscription price for the product
  
  <Expandable title="properties">
    <ParamField path="amount" type="number">
      Price in cents (e.g., 2900 for $29.00)
    </ParamField>
    <ParamField path="interval" type="string">
      Billing frequency: `month`, `year`, `quarter`, `week`, `one_off`
    </ParamField>
    <ParamField path="interval_count" type="number">
      Number of intervals between charges (e.g., 3 for quarterly)
    </ParamField>
  </Expandable>
</ParamField>

<ParamField path="items" type="array" required>
  Array of plan items that define feature entitlements and pricing
</ParamField>

<ParamField path="add_on" type="boolean" default="false">
  Whether this is an add-on product that can be attached alongside a main product
</ParamField>

<ParamField path="auto_enable" type="boolean" default="false">
  Whether to automatically attach this product to all customers
</ParamField>

## Product Types

### Main Products

Main products are the primary subscriptions customers purchase:

```json Example: Pro Plan
{
  "id": "pro",
  "name": "Pro Plan",
  "description": "For growing teams",
  "add_on": false,
  "price": {
    "amount": 2900,
    "interval": "month"
  },
  "items": [
    {
      "feature_id": "api-calls",
      "included": 10000,
      "unlimited": false,
      "reset": {
        "interval": "month"
      }
    }
  ]
}
```

### Add-On Products

Add-ons supplement main products with additional features or capacity:

```json Example: Extra Storage Add-On
{
  "id": "extra-storage",
  "name": "Extra Storage",
  "add_on": true,
  "price": {
    "amount": 500,
    "interval": "month"
  },
  "items": [
    {
      "feature_id": "storage-gb",
      "included": 100,
      "unlimited": false
    }
  ]
}
```

<Note>
Customers can have multiple add-ons but typically only one main product.
</Note>

### One-Off Products

One-off products are purchased once without recurring billing:

```json Example: Premium Support Package
{
  "id": "premium-support",
  "name": "Premium Support Package",
  "price": {
    "amount": 49900,
    "interval": "one_off"
  }
}
```

### Free Products

Free products have no pricing but grant entitlements:

```json Example: Free Plan
{
  "id": "free",
  "name": "Free Plan",
  "price": null,
  "items": [
    {
      "feature_id": "api-calls",
      "included": 1000,
      "unlimited": false,
      "reset": {
        "interval": "month"
      }
    }
  ]
}
```

## Plan Items

Plan items define the features included in a product and their configuration. Each item connects a feature to the product with specific entitlement rules.

### Basic Plan Item

<ParamField path="feature_id" type="string" required>
  ID of the feature this item provides
</ParamField>

<ParamField path="included" type="number" required>
  Quantity or allowance included (e.g., 10000 API calls)
</ParamField>

<ParamField path="unlimited" type="boolean" required>
  Whether the feature has unlimited access
</ParamField>

<ParamField path="reset" type="object">
  When the allowance resets
  
  <Expandable title="properties">
    <ParamField path="interval" type="string">
      Reset frequency: `month`, `year`, `week`, `day`, `hour`, `lifetime`
    </ParamField>
    <ParamField path="interval_count" type="number">
      Number of intervals between resets
    </ParamField>
  </Expandable>
</ParamField>

```json Example: Monthly API Allowance
{
  "feature_id": "api-calls",
  "included": 10000,
  "unlimited": false,
  "reset": {
    "interval": "month",
    "interval_count": 1
  }
}
```

### Plan Items with Pricing

Plan items can have their own pricing for usage-based billing:

<ParamField path="price" type="object">
  Usage-based pricing configuration
  
  <Expandable title="properties">
    <ParamField path="amount" type="number">
      Per-unit price in cents (for simple pricing)
    </ParamField>
    <ParamField path="tiers" type="array">
      Volume-based pricing tiers (mutually exclusive with amount)
    </ParamField>
    <ParamField path="billing_method" type="string">
      `prepaid` or `usage_based` (arrears)
    </ParamField>
    <ParamField path="billing_units" type="number">
      How many units are billed together (e.g., 100 for per-hundred)
    </ParamField>
    <ParamField path="interval" type="string">
      Billing frequency
    </ParamField>
    <ParamField path="max_purchase" type="number">
      Maximum units that can be purchased (null for unlimited)
    </ParamField>
  </Expandable>
</ParamField>

```json Example: Prepaid API Calls
{
  "feature_id": "api-calls",
  "included": 5000,
  "unlimited": false,
  "reset": {
    "interval": "month"
  },
  "price": {
    "amount": 10,
    "billing_method": "prepaid",
    "billing_units": 100,
    "interval": "month",
    "max_purchase": null
  }
}
```

<Info>
In this example, customers get 5,000 API calls included, and can purchase additional blocks of 100 calls for $0.10 each.
</Info>

### Tiered Pricing

Implement volume discounts with pricing tiers:

```json Example: Tiered Usage Pricing
{
  "feature_id": "api-calls",
  "included": 0,
  "unlimited": false,
  "price": {
    "tiers": [
      {
        "to": 10000,
        "amount": 10
      },
      {
        "to": 100000,
        "amount": 8
      },
      {
        "to": "infinite",
        "amount": 5
      }
    ],
    "billing_method": "usage_based",
    "billing_units": 1000,
    "interval": "month"
  }
}
```

<Note>
First 10k calls: $0.01 each<br/>
10k-100k calls: $0.008 each<br/>
100k+ calls: $0.005 each
</Note>

## Billing Methods

Autumn supports two billing methods for usage-based charges:

### Prepaid Billing

Customers purchase capacity upfront:

```json Example: Prepaid Credits
{
  "billing_method": "prepaid",
  "amount": 1000,
  "billing_units": 1000
}
```

**Characteristics:**
- Payment collected immediately
- Balance decrements as usage occurs
- Customer can purchase more at any time
- No surprise bills at end of cycle

### Usage-Based Billing (Arrears)

Customers are billed for actual usage at period end:

```json Example: Pay-as-you-go
{
  "billing_method": "usage_based",
  "amount": 10,
  "billing_units": 1
}
```

**Characteristics:**
- Usage tracked throughout billing cycle
- Invoice generated at period end
- Payment collected after consumption
- Suitable for variable workloads

## Billing Intervals

Autumn supports multiple billing intervals:

<ParamField path="interval" type="string">
  Billing frequency options:
  - `one_off` - Single payment, no recurrence
  - `week` - Weekly billing
  - `month` - Monthly billing
  - `quarter` - Every 3 months
  - `semi_annual` - Every 6 months
  - `year` - Annual billing
</ParamField>

```json Example: Annual Plan with Discount
{
  "id": "pro-annual",
  "name": "Pro Plan (Annual)",
  "price": {
    "amount": 29000,
    "interval": "year"
  }
}
```

## Free Trials

Offer free trial periods to new customers:

<ParamField path="free_trial" type="object">
  Free trial configuration
  
  <Expandable title="properties">
    <ParamField path="duration_length" type="number">
      Length of the trial period
    </ParamField>
    <ParamField path="duration_type" type="string">
      Unit of duration: `day`, `week`, `month`
    </ParamField>
    <ParamField path="card_required" type="boolean">
      Whether payment method is required upfront
    </ParamField>
  </Expandable>
</ParamField>

```json Example: 14-Day Trial
{
  "id": "pro",
  "name": "Pro Plan",
  "price": {
    "amount": 2900,
    "interval": "month"
  },
  "free_trial": {
    "duration_length": 14,
    "duration_type": "day",
    "card_required": false
  }
}
```

<Info>
With `card_required: false`, customers get full access without payment info. Trial converts to paid subscription only after they add a payment method.
</Info>

## Rollover Configuration

Allow unused allowances to carry over to the next period:

<ParamField path="rollover" type="object">
  Rollover configuration for plan items
  
  <Expandable title="properties">
    <ParamField path="max" type="number">
      Maximum amount that can roll over (null for unlimited)
    </ParamField>
    <ParamField path="expiry_duration_type" type="string">
      When rolled over balance expires: `never`, `period`, `custom`
    </ParamField>
    <ParamField path="expiry_duration_length" type="number">
      Number of periods before expiry (for custom)
    </ParamField>
  </Expandable>
</ParamField>

```json Example: Rollover with Cap
{
  "feature_id": "api-calls",
  "included": 10000,
  "reset": {
    "interval": "month"
  },
  "rollover": {
    "max": 5000,
    "expiry_duration_type": "never"
  }
}
```

<Note>
In this example, unused API calls roll over, but only up to 5,000 maximum.
</Note>

## Proration Settings

Control how mid-cycle upgrades and downgrades are handled:

<ParamField path="proration" type="object">
  Proration behavior for plan item changes
  
  <Expandable title="properties">
    <ParamField path="on_increase" type="string">
      Behavior when upgrading:
      - `bill_immediately` - Charge difference now
      - `prorate_immediately` - Prorated charge now
      - `prorate_next_cycle` - Credit on next invoice
      - `bill_next_cycle` - Full charge next cycle
    </ParamField>
    <ParamField path="on_decrease" type="string">
      Behavior when downgrading:
      - `prorate` - Issue credit
      - `prorate_immediately` - Immediate credit
      - `prorate_next_cycle` - Credit next cycle
      - `none` - No proration
      - `no_prorations` - No credits issued
    </ParamField>
  </Expandable>
</ParamField>

```json Example: Proration Configuration
{
  "proration": {
    "on_increase": "prorate_immediately",
    "on_decrease": "prorate_next_cycle"
  }
}
```

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="What's the difference between 'product' and 'plan'?">
    They're the same thing. Autumn uses both terms interchangeably:
    - API endpoints use `/plans`
    - Documentation often says "product"
    - The data model is `product`
    
    We're standardizing on "product" but maintaining backward compatibility.
  </Accordion>

  <Accordion title="Can I change product pricing for existing customers?">
    No, pricing changes only affect new subscriptions. To change pricing:
    1. Update the product's price
    2. New customers get new pricing
    3. Existing customers keep their original pricing
    
    To migrate existing customers, you need to:
    1. Cancel their current subscription
    2. Attach them to the updated product
  </Accordion>

  <Accordion title="How do I implement annual discount pricing?">
    Create separate product variants:
    ```json
    {
      "id": "pro-monthly",
      "price": { "amount": 2900, "interval": "month" },
      "base_variant_id": "pro"
    }
    {
      "id": "pro-annual",
      "price": { "amount": 29000, "interval": "year" },
      "base_variant_id": "pro"
    }
    ```
    Annual saves $5,800 (17% discount).
  </Accordion>

  <Accordion title="Can a product include multiple features?">
    Yes! Products typically include multiple features:
    ```json
    {
      "items": [
        { "feature_id": "api-calls", "included": 10000 },
        { "feature_id": "storage-gb", "included": 50 },
        { "feature_id": "team-members", "included": 5 }
      ]
    }
    ```
  </Accordion>

  <Accordion title="What happens to plan items when interval and reset differ?">
    They must match. If you set both `reset.interval` and `price.interval`, they must be the same value. This validation prevents inconsistent billing configurations.
  </Accordion>

  <Accordion title="How do I create a free plan with upgrade options?">
    Create a free product with limited entitlements:
    ```json
    {
      "id": "free",
      "name": "Free Plan",
      "price": null,
      "items": [
        { "feature_id": "api-calls", "included": 1000 }
      ]
    }
    ```
    
    Then use `/attach` to upgrade customers to paid plans.
  </Accordion>
</AccordionGroup>
