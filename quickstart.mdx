## Prerequisites

Before you begin, make sure you have the following installed:

- [Bun](https://bun.sh) - Fast JavaScript runtime and package manager
- [Docker](https://www.docker.com/get-started) - For running services with Docker Compose
- [Git](https://git-scm.com/) - For cloning the repository

## Installation

<Steps>
  <Step title="Clone the Repository">
    Clone the Autumn repository from GitHub:

    ```bash
    git clone https://github.com/useautumn/autumn.git
    cd autumn
    ```
  </Step>

  <Step title="Install Dependencies">
    Install all project dependencies using Bun:

    ```bash
    bun install
    ```

    This will install dependencies for all workspaces including:
    - `server` - Backend API server
    - `vite` - Frontend dashboard
    - `shared` - Shared types and schemas
    - `apps/checkout` - Checkout page
  </Step>

  <Step title="Run Setup Script">
    Run the interactive setup script to configure your environment:

    ```bash
    bun setup
    ```

    The setup script will:
    - Generate secure authentication secrets (BETTER_AUTH_SECRET, ENCRYPTION_IV, ENCRYPTION_PASSWORD)
    - Create a unique localtunnel subdomain for Stripe webhooks
    - Guide you through database setup options:
      - **Set up Supabase (Cloud)** - Automatically create and configure a Supabase database (recommended)
      - **Paste your own DATABASE_URL** - Use your existing PostgreSQL instance
      - **Configure later** - Skip database setup for now
    - Generate `server/.env` and `vite/.env` files with your configuration

    <Note>
      If you choose Supabase setup, the script will prompt you to login and optionally create a new organization if needed. Your database credentials will be automatically configured.
    </Note>
  </Step>

  <Step title="Generate and Migrate Database">
    Create the database schema and run migrations:

    ```bash
    bun db:generate && bun db:migrate
    ```

    This generates Drizzle ORM types and creates all necessary tables in your PostgreSQL database.
  </Step>

  <Step title="Start Autumn">
    Launch all services using Docker Compose:

    <CodeGroup>
      ```bash Windows
      docker compose -f docker-compose.dev.yml up
      ```

      ```bash macOS/Linux
      docker compose -f docker-compose.unix.yml up
      ```
    </CodeGroup>

    This starts the following services:
    - **Valkey** (Redis-compatible) on port 6379 - In-memory data store for caching and rate limiting
    - **Vite Frontend** on port 3000 - Dashboard UI
    - **Server** on port 8080 - API backend
    - **Workers** - BullMQ background job processors
    - **Localtunnel** - Exposes your local server for Stripe webhooks

    <Tip>
      The first build may take a few minutes. Subsequent starts will be much faster.
    </Tip>
  </Step>

  <Step title="Access the Dashboard">
    Open your browser and navigate to:

    ```
    http://localhost:3000
    ```

    You'll see the Autumn sign-in page.
  </Step>

  <Step title="Sign In">
    Enter your email address at the sign-in page. Since you're running locally without email configuration, your OTP (one-time password) will appear in your terminal console.

    <Warning>
      In production, configure Resend or Google OAuth in `server/.env` to enable proper email delivery:
      
      ```bash server/.env
      # Resend for email OTP
      RESEND_API_KEY=your_resend_api_key
      RESEND_DOMAIN=your_domain.com
      
      # Google OAuth (optional)
      GOOGLE_CLIENT_ID=your_google_client_id
      GOOGLE_CLIENT_SECRET=your_google_client_secret
      ```
    </Warning>

    Copy the OTP from your terminal and paste it into the sign-in form.
  </Step>
</Steps>

## Understanding the Stack

Autumn is built as a monorepo using Bun workspaces:

```
autumn/
├── server/          # Hono backend API
├── vite/            # React + Vite dashboard
├── shared/          # Shared types, schemas, and utilities
├── apps/
│   └── checkout/    # Embeddable checkout pages
└── scripts/         # Setup and utility scripts
```

### Key Technologies

- **Bun** - Runtime, package manager, and test runner
- **Hono** - Lightweight web framework for the API
- **React + Vite** - Frontend dashboard
- **Drizzle ORM** - Type-safe database queries
- **PostgreSQL** - Primary database
- **Valkey (Redis)** - Caching and real-time usage metering
- **BullMQ** - Background job processing
- **Stripe** - Payment processing
- **Docker** - Containerization and local development

## Troubleshooting

<AccordionGroup>
  <Accordion title="SyntaxError: Unexpected end of JSON input">
    This error can occur when running `bun setup` multiple times. It's a [known issue](https://github.com/drizzle-team/drizzle-orm/issues/4529) with Drizzle ORM migrations.

    **Solution:**
    1. Connect to your database
    2. Drop all existing tables
    3. Run the setup script again:
       ```bash
       bun setup
       bun db:generate && bun db:migrate
       ```
  </Accordion>

  <Accordion title="Database Connection Failed">
    If you can't connect to your database:

    1. Verify your `DATABASE_URL` in `server/.env` is correct
    2. Ensure your PostgreSQL instance is running
    3. Check that your database allows connections from your IP
    4. For Supabase users, verify you're using the connection pooler URL (port 5432)
  </Accordion>

  <Accordion title="Port Already in Use">
    If you see errors about ports 3000, 8080, or 6379 already being in use:

    ```bash
    # Find and kill processes using these ports
    lsof -ti:8080 -ti:3000 -ti:6379 | xargs kill -9
    ```

    Or use the convenient npm script:
    ```bash
    bun run q
    ```
  </Accordion>

  <Accordion title="Docker Build Issues">
    If Docker builds are failing:

    1. Ensure Docker Desktop is running
    2. Clear Docker cache:
       ```bash
       docker system prune -a
       ```
    3. Try building individual services:
       ```bash
       docker compose -f docker-compose.dev.yml build --no-cache
       ```
  </Accordion>
</AccordionGroup>

## Development Workflow

Once you have Autumn running, all services support hot reloading:

- Edit files in `vite/` - Frontend automatically reloads
- Edit files in `server/` - Backend automatically restarts
- Edit files in `shared/` - Changes propagate to dependent services

<Tip>
  The Docker Compose setup uses volume mounts for hot reloading. If changes aren't being detected on Windows, the `docker-compose.dev.yml` includes polling configuration.
</Tip>
